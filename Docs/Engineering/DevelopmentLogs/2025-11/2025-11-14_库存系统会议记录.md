## 当前现状

## 2025-11-15 附加约束
- 玩家账号层存在两个平行组件：`UResourceInventoryComponent`（堆叠资源仓库）与 `UShootInventoryManagerComponent`（有身份背包）。前者只用于材料/货币/徽章/设计图等数量型资源，并始终参与 SaveGame；后者掌管所有武器/装备/可实例化消耗品，QuickBar、EquipmentManager 与武器 GA 只能与该组件交互。
- 物品实例需要 `EShootItemLifetime` 字段（`Persistent` / `RuntimeOnly`），InventoryManager 必须实现 `AddPersistentItem` 与 `AddRuntimeItem`。Hub/制作/奖励等账号行为走 Persistent 流程，副本内拾取的武器走 RuntimeOnly，并在副本结束时统一清空，不写存档、不改 QuickBar 配置。
- SaveGame 仅记录 Persistent 实例和 QuickBar 绑定，RuntimeOnly 仅在当前副本存在。ResourceInventory 不引入 RuntimeOnly 概念，所有数量型资源仍是 Persistent；若有战斗内一次性增益，请直接由拾取或 Ability 处理。
- 所有库存/武器相关 C++ 代码在实现 CreateDefaultSubobject、AddResource/AddItem 等逻辑时，需要补充中文注释说明“ResourceInventory = 数量型仓库 / InventoryManager = 有身份背包 / QuickBar 只引用 InventoryManager”，方便 AI/同事阅读代码即可理解架构。
- 文档侧：AGENTS.md、InventorySystem 任务包（DesignSpec/Implementation/Checklist/STATUS）已加入上述规则；后续修改必须保持一致，并在 DevelopmentNotes 中登记。

## 2025-11-15 交互系统补充
- 交互主体拆分：PlayerControlled（ASC 在 PlayerState，拥有账号仓库/QuickBar）与 AIControlled（ASC 在 Pawn，无账号层）。`UShootAbility_InteractCore` 为玩家专用能力，AI 若需交互须走 AutoOverlap 或独立脚本/行为树任务。
- 拾取/交互物新增 `EShootInteractionTriggerMode` 与 `EShootInteractionUserFilter` 配置：`PressToInteract` + Player 走交互能力，`AutoOverlap` 可用于玩家或 AI 自动触发，`AIScripted` 供 AI 行为树调用。
- 交互效果改为阵营驱动：根据 Instigator 的 Faction Tag 查表应用 GameplayEffect（玩家扣血/AI 回血等差异在数据中配置），禁止在 GA/拾取 Actor 中硬编码 `if(IsPlayer)`。
- `UShootGA_Interaction_Collect` 根据拾取配置分流账号资源、Persistent 物品与 RuntimeOnly 临时武器；所有账号数据修改仅能在服务器端通过 PlayerState 组件完成，客户端只播放表现。
- `AShootResourcePickup` 的 AutoOverlap 流程继续使用，同时实现 `IInteractableTarget` 时可返回交互选项并通过 `TriggerMode` 切换是否需要按键；自动拾取与按键交互两条路径并存，互不干扰。

## 2025-11-16 技术补丁
- Ability 成本失败提示：新增 `Ability.ActivateFail.Cost` GameplayTag（参见 `Config/DefaultGameplayTags.ini`），`UShootAbilityCost_ItemTagStack` 构造中改为 `RequestGameplayTag`，避免在 GameplayTags 单例初始化前访问 FShootGameplayTags。
- Iris 复制依赖（详细记录）：
  1. **症状**：链接 `UnrealEditor-NewWorldOrder.dll` 时出现 `LNK2019`，指向 `__imp_?CreateAndRegisterFragmentsForObject@FReplicationFragmentUtil@Net@UE@@...`，调用栈来自 `UShootEquipmentInstance::RegisterReplicationFragments`。
  2. **原因**：Iris 复制 API 位于 `IrisCore` 模块；`FReplicationFragmentUtil` 是延迟导入符号，仅在构建文件中声明依赖时才会被链接。
  3. **解决**：将 `IrisCore` 添加到 `NewWorldOrder.Build.cs` → `PrivateDependencyModuleNames`。重新生成项目后 UE 会链接 `UE::Net` Runtime，`CreateAndRegisterFragmentsForObject` 得到实现。
  4. **结论**：任何使用 `UE::Net::FFragmentRegistrationContext`/`FReplicationFragmentUtil` 的 UObject，需要在 Build.cs 明确依赖 `IrisCore`；否则仅在链接阶段才会暴露错误，排查成本高。

## Lyra 武器分层与客户端预测（GPT5 摘要，便于 Claude/Codex 快速对齐）
- 武器四层数据/资产：
  - ID_XXX（InventoryItemDefinition）：DisplayName + Fragments（EquippableItem→WID、QuickBarIcon、PickupIcon、SetStats 等）。
  - WID_XXX（EquipmentDefinition）：InstanceType=ULyraRangedWeaponInstance 蓝图、AbilitySetsToGrant（射击/换弹 GA）、ActorsToSpawn（B_Weapon_XXX 挂接）。
  - B_WeaponInstance_XXX（RangedWeaponInstance 蓝图 UObject）：武器逻辑数据（散布、伤害、节奏、动画层配置），不在场景。
  - B_Weapon_XXX（Actor 蓝图）：纯表现（Mesh/特效/音效），通过 GameplayCue/事件响应开火、换弹。
- QuickBar/Equip 流程（Lyra 标准）：Inventory 拿到 ItemInstance → QuickBar 槽位持 ItemInstance → Equippable Fragment 提取 WID → EquipmentManager 生成 WeaponInstance(UObject)+WeaponActor(AActor)+授予 GA → WeaponInstance.Instigator 指回 ItemInstance（读取 StatTags/弹药）。
- 开火客户端预测流水线：
  - 输入触发 GA_Weapon_Fire_*（父类 ULyraGameplayAbility_RangedWeapon）。
  - 客户端 StartRangedWeaponTargeting：相机射线/散布→生成 TargetData→CallServerSetReplicatedTargetData RPC。
  - 同时本地 CommitAbility：`ULyraAbilityCost_ItemTagStack` 从 ItemInstance.StatTags 扣弹，播放动画、特效、命中表现（GameplayCue）。
  - 服务器收到 TargetData：同一 GA 服务器分支应用伤害 GE（未重算射线，信任客户端命中）。
- 交付给 Claude 的关键信息：ID/WID/WeaponInstance/WeaponActor 分层、QuickBar→EquipmentManager→Instigator 链路、GA 预测流程（客户端射线+本地扣弹/特效，服务器基于 TargetData 结算伤害）。***
## 需求扩展（用户 + GPT5 对齐）
- 项目必须同时满足“战斗期物品（Lyra Inventory）+ 账号级资源/配方/解锁（自研 Resource System）”两层需求：
  - 战斗层：武器/战斗消耗品依旧由 Lyra Inventory/Equipment/QuickBar/Weapon GA 负责。
  - 账号层：材料（军用合金、服装碎片等）、势力徽章、传说武器设计图、金币、成就/配方进度等必须由独立的“资源仓库 + SaveGame”管理，并在 Hub/制作系统中消费。
- 物品定义全部统一到 `UShootInventoryItemDefinition` + Fragment 模式，新增字段/Fragment 以描述：
  - `EItemCategory`（Weapon, Consumable, Material, Currency, KeyItem, Blueprint, CostumeToken）。
  - Stackable、CurrencyTag、CraftingMeta 等 Fragment，用于控制堆叠上限/游戏标签/稀有度 UI。
- 资源仓库建议实现为 PlayerState 组件（示例：`UResourceInventoryComponent`）：
  - 存储 `TArray<FResourceEntry{ItemDef, Count}>`，支持 Add/Consume/GetCount，兼容 SaveGame 与复制。
  - 材料、徽章、设计图、金币等通过该组件维护，不直接塞进 Lyra Inventory。
- SaveGame 策略：
  - `FSavedResourceEntry`（PrimaryAssetId + Count）持久化资源。
  - `FSavedWeaponEntry` 持久化拥有武器/强化数据；加载时再转换为 Runtime 的 Inventory ItemInstance + Equipment。
  - Hub 读取存档初始化 Resource + 武器列表，副本结算/关键节点时写回。
- 掉落与制作：
  - 材料拾取 Actor 仅负责播放视觉效果→调用 ResourceComponent->AddResource→显示 UI 提示，自动堆叠。
  - 制作配方使用 DataAsset（`UWeaponCraftRecipe`）描述输入/输出：检查资源→扣除→调用 InventoryManager->AddItemDefinition 产生武器→播放 3s 动画。
  - 服装合成/传说装备解锁与武器制作共用同一套 Recipe + Resource 接口。
- QuickBar/UCombatComponent 重构要求：
  - 槽位保存 `UShootInventoryItemInstance` 引用。
  - Equip/Unequip 通过 EquipmentManager + Equippable Fragment 完成，Instigator 指回 ItemInstance（Weapon 访问 StatTags/Resource）。
  - UI 数据从 InventoryMessage/ResourceComponent 获取，Ammo/材料不再直接读 Actor 字段。
