# 武器实例分层改造

日期：2025-11-02
负责人：AI
状态：已完成

## 背景

旧的ARangedWeaponInstance同时承载通用状态与命中特有逻辑，扩展投射物时基类不断膨胀，且与Lyra的Definition/Instance/Actor分层不符。

## 任务描述

目标：
- 统一榴弹、火箭筒等爆炸武器的GAS流程
- 避免直接搬运非GAS框架代码
- 建立清晰的武器分层架构

## 实现过程

第一步：分析现有问题
- ARangedWeaponInstance包含散布、扩散恢复等Hitscan特有逻辑
- 投射物武器不需要这些逻辑，但继承了基类
- 基类膨胀，违反单一职责原则

第二步：设计分层架构
```
UWeaponDefinition（通用字段）
├── UHitscanWeaponDefinition（命中型）
│   └── 散布、扩散恢复、多弹丸
└── UProjectileWeaponDefinition（投射物型）
    └── 初速度、引信、爆炸半径

ARangedWeaponInstance（通用）
├── AHitscanWeaponInstance（命中型）
│   └── 散布计算、弹丸追踪
└── AProjectileWeaponInstance（投射物型）
    └── 投射物生成配置
```

第三步：实现分层
- 新增UHitscanWeaponDefinition和AHitscanWeaponInstance
- 新增UProjectileWeaponDefinition
- ARangedWeaponInstance保留通用字段（伤害、插槽、弹药）
- 所有命中类GA改为依赖AHitscanWeaponInstance
- 投射物GA独立复用ARangedWeaponInstance + Projectile

第四步：投射物核心链路
1. UShootGA_Weapon_Fire_Projectile只在服务器端生成AShootProjectileBase
2. 客户端通过GameplayCue获取表现
3. ARangedWeaponInstance新增bIsProjectileWeapon、ProjectileClass、ProjectileDamageEffect、ProjectileConfig
4. AShootProjectileBase负责：
   - 复制配置
   - 设置UProjectileMovementComponent
   - 服务器端ApplyGameplayEffectSpecToTarget（SetByCaller.Damage）
   - 调用ExecuteGameplayCue同步所有客户端

第五步：扩展点设计
- AShootProjectileRocket：直射、无重力
- AShootProjectileGrenade：允许弹跳、引信超时爆炸
- 蓝图扩展：OnProjectileBounce监听（音效/特效），但爆炸逻辑在C++保持服务器权威

## 数据配置注意事项

GA配置：
- 若未设置ProjectileClassOverride/ProjectileDamageEffectOverride，会自动读取武器定义
- 若两者皆为空则打印警告并放弃生成

FProjectileWeaponConfig配置：
- DamageFalloff = 0 表示无衰减
- DamageInnerRadius建议填写，否则距离计算会出现除零保护
