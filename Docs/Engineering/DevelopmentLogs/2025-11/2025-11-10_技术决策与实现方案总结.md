## 1. 项目需求与背景

### 核心需求
- **双主角动作游戏**: 男性和女性主角，单存档包含两角色完整数据
- **三种游戏模式统一架构**:
  1. 单人模式: 单玩家控制一个主角
  2. 本地分屏合作: 两个本地玩家(仅战斗副本)，类似《双人成行》
  3. 在线合作: 两个远程玩家通过Steam P2P联机
- **三级地图架构**:
  - **MainMenu**: 3D场景 + UI，存档选择和角色预览
  - **Hub(家园)**: 单人探索区域，角色定制和准备
  - **Dungeon(副本)**: 战斗关卡，支持单人/分屏/联机

### 核心挑战
1. 如何用单一Listen-Server架构统一三种游戏模式
2. 如何处理Session生命周期避免状态残留
3. 如何实现ASC(Ability System Component)跨地图持久化
4. 如何清理战斗状态避免污染非战斗区域
5. 如何快速加载MainMenu同时支持多存档

## 2. 技术限制与发现

### 2.1 UE Session生命周期限制

**关键发现1: DestroySession的Host/Client行为差异**
- **Host调用DestroySession**: 通知所有Client断开，销毁整个Session
- **Client调用DestroySession**: 仅影响本地状态，离开Session
- **影响**: Host和Client必须使用不同的退出流程

**关键发现2: ReturnToMainMenu触发Hard Travel**
```cpp
// Engine/Source/Runtime/Engine/Private/GameMode.cpp
void AGameModeBase::ReturnToMainMenuHost()
{
    // 触发 Hard Travel 到 DefaultMap
    GetWorld()->ServerTravel(TransitionMap);
}
```
- Hard Travel会重建所有对象(PlayerController, PlayerState, ASC)
- 必须在DestroySession完成后才能调用，否则会留下Session残留

**关键发现3: Session残留导致下次创建失败**
```cpp
// 问题场景
1. 创建Session进入Lobby
2. 未DestroySession直接ReturnToMainMenu
3. 再次点击"创建房间"
4. GetNamedSession(NAME_GameSession) != nullptr
5. CreateSession失败或行为异常
```

**技术限制1: 必须实现Session清理守卫**
```cpp
// 正确流程
void UMultiplayerSessionsSubsystem::CreateSession(...)
{
    FNamedOnlineSession* ExistingSession = SessionInterface->GetNamedSession(SessionName);
    if (ExistingSession != nullptr) {
        // 自动清理残留Session
        DestroySession(SessionName);
        return; // 等待OnDestroySessionComplete回调后重新创建
    }
    // 正常创建
}
```

| 特性 | Seamless Travel | Hard Travel |

| Character/Pawn | 重建 | 重建 |
| GameMode | 重建 | 重建 |
| 用法 | `ServerTravel(Map, true)` | `OpenLevel()`, `ReturnToMainMenu()` |

### 2.3 GAS(Gameplay Ability System)限制

**技术限制3: 运行时不应移除AttributeSet**
```cpp
//  危险操作 - 可能导致崩溃
ASC->RemoveSpawnedAttribute(CombatAttributeSet);

// 正确做法 - 清理Effect和Ability
FGameplayTagContainer CombatTags;
CombatTags.AddTag(FGameplayTag::RequestGameplayTag("Combat"));

ASC->CancelAbilities(&CombatTags);  // 取消战斗技能
ASC->RemoveActiveEffectsWithTags(CombatTags);  // 移除战斗Buff/Debuff

// 重置属性到初始值
UAttributeSet* AttrSet = ASC->GetAttributeSet(UCombatAttributeSet::StaticClass());
UCombatAttributeSet* CombatAttr = Cast<UCombatAttributeSet>(AttrSet);
if (CombatAttr)
{
    ASC->SetNumericAttributeBase(CombatAttr->GetHealthAttribute(),
                                 CombatAttr->GetMaxHealth());
}
```

**关键发现5: ASC分层架构最佳实践**
- **Meta层AttributeSet**(Hub使用): 货币、解锁进度、章节进度
- **Combat层AttributeSet**(Dungeon使用): Health, Mana, 攻击力, 防御力
- **动态加载**: 进入Dungeon时`AddAttributeSet(CombatAS)`
- **清理而非移除**: 退出Dungeon时清理Effect，不移除AttributeSet

### 2.4 Listen-Server架构限制

**关键发现6: 三种模式的本质统一**
```cpp
// 单人模式
CreateSession() 不调用，本地Listen Server无其他玩家连接

// 本地分屏
GetGameInstance()->CreateLocalPlayer(1);  // 添加第二个本地玩家
// 退出时: GetGameInstance()->RemoveLocalPlayer(Player);

// 在线合作
Host: CreateSession() + StartSession()
Client: FindSessions() + JoinSession(Result)
// 底层都是Listen Server架构
```

**技术限制4: 分屏仅在Dungeon启用**
- Hub必须单人(否则另一角色数据来源不明确)
- Lobby是在线匹配区域，不支持分屏
- Dungeon在本地分屏模式下动态CreateLocalPlayer

### 3.1 IOnlineSession接口核心方法

```cpp
class IOnlineSession
{
    // 创建Session(异步)
    virtual bool CreateSession(int32 HostingPlayerNum,
                               FName SessionName,
                               const FOnlineSessionSettings& NewSessionSettings) = 0;

    // 查找Sessions(异步)
    virtual bool FindSessions(int32 SearchingPlayerNum,
                              const TSharedRef<FOnlineSessionSearch>& SearchSettings) = 0;

    // 加入Session(异步)
    virtual bool JoinSession(int32 LocalUserNum,
                            FName SessionName,
                            const FOnlineSessionSearchResult& DesiredSession) = 0;

    // 启动Session(异步) - Host在所有玩家Ready后调用
    virtual bool StartSession(FName SessionName) = 0;

    // 结束Session(异步) - 标记Session结束但不销毁
    virtual bool EndSession(FName SessionName) = 0;

    // 销毁Session(异步)
    virtual bool DestroySession(FName SessionName,
                                const FOnDestroySessionCompleteDelegate& CompletionDelegate) = 0;

    // 查询Session状态(同步)
    virtual EOnlineSessionState::Type GetSessionState(FName SessionName) const = 0;

    // 获取已创建的Session(同步)
    virtual FNamedOnlineSession* GetNamedSession(FName SessionName) = 0;
};
```

## 4. 最终解决方案

### 4.1 游戏流程架构

**单人/分屏流程(离线)**
```
MainMenu (Hard Travel)
    ↓ 选择存档 + "开始游戏"
Hub (Hard Travel, 单人探索)
    ↓ 选择副本 + "进入副本" (Seamless Travel)
Dungeon (战斗关卡)
    ↓ 完成副本 (Seamless Travel)
Hub (返回家园)
```

**在线流程**
```
MainMenu (Hard Travel)
    ↓ 选择存档 + "在线游戏"
Lobby Level (Hard Travel, CreateSession或JoinSession)
    ↓ Host点击"开始游戏" (Seamless Travel)
Dungeon (战斗关卡)
    ↓ 完成副本 (Seamless Travel)
Lobby Level (返回大厅，可继续组队)
    ↓ "退出房间" (DestroySession + Hard Travel)
MainMenu
```

**关键设计决策**:
1. **Hub仅单人**: 避免在线模式下另一角色数据来源混乱
2. **Lobby必须是Level**: 不能是Widget，因为ServerTravel需要目标地图
3. **在线返回Lobby而非MainMenu**: 允许继续组队打下一个副本
4. **分屏仅在Dungeon**: Hub和Lobby不支持分屏，进入Dungeon时动态CreateLocalPlayer

### 4.2 Session管理方案

**创建Session前检查**
```cpp
void UMultiplayerSessionsSubsystem::CreateSession(FName SessionName, int32 NumPublicConnections, ...)
{
    // 检查是否有残留Session
    FNamedOnlineSession* ExistingSession = SessionInterface->GetNamedSession(SessionName);
    if (ExistingSession != nullptr)
    {
        // 缓存参数
        LastNumPublicConnections = NumPublicConnections;
        // ...

        // 先销毁残留Session
        DestroySession(SessionName);
        return;  // OnDestroySessionComplete回调中重新创建
    }

    // 正常创建Session
    LastSessionSettings = MakeShareable(new FOnlineSessionSettings());
    LastSessionSettings->NumPublicConnections = NumPublicConnections;
    LastSessionSettings->bShouldAdvertise = true;
    // ...

    SessionInterface->CreateSession(*LocalPlayer->GetPreferredUniqueNetId(), SessionName, *LastSessionSettings);
}

void UMultiplayerSessionsSubsystem::OnDestroySessionComplete(FName SessionName, bool bWasSuccessful)
{
    // 如果有缓存的创建参数，重新创建
    if (bWasSuccessful && LastNumPublicConnections > 0)
    {
        CreateSession(SessionName, LastNumPublicConnections, ...);
        LastNumPublicConnections = 0;  // 清除缓存
    }
}
```

**退出房间流程(Host)**
```cpp
void AMyGameMode::HostLeaveSession()

    // 销毁Session(会通知所有Client)
```

**战斗状态清理(Dungeon → Hub)** - 使用实际Tag命名:
```cpp
void AShootPlayerState::OnExitDungeon()
{
    UAbilitySystemComponent* ASC = GetAbilitySystemComponent();
    if (!ASC) return;

    // 1. 取消所有动作类技能
    FGameplayTagContainer ActionAbilities;
    ActionAbilities.AddTag(FGameplayTag::RequestGameplayTag("Ability.Type.Action"));
    ASC->CancelAbilities(&ActionAbilities);

    // 2. 移除所有战斗相关GameplayEffect
    // 注意: 需要根据实际Effect设计添加相应的Tag
    FGameplayTagContainer TemporaryEffects;
    TemporaryEffects.AddTag(FGameplayTag::RequestGameplayTag("GameplayCue.Character"));
    ASC->RemoveActiveEffectsWithTags(TemporaryEffects);

    // 3. 重置战斗属性到满值
    if (UShootAttributeSet* AttrSet = GetAttributeSet())
    {
        // 恢复满血
        ASC->SetNumericAttributeBase(AttrSet->GetHealthAttribute(),
                                     AttrSet->GetMaxHealth());
```

```cpp
// MultiplayerSessionsSubsystem.cpp
void UMultiplayerSessionsSubsystem::CreateSession(FName SessionName, int32 NumPublicConnections, bool bIsLanMatch)
{
    if (!SessionInterface.IsValid()) return;

    // 关键: 检查并清理残留Session
    FNamedOnlineSession* ExistingSession = SessionInterface->GetNamedSession(SessionName);
    if (ExistingSession != nullptr)
    {
        // 缓存参数
        LastNumPublicConnections = NumPublicConnections;
        bLastIsLanMatch = bIsLanMatch;

        // 先销毁再创建
        DestroySession(SessionName);
        return;
    }

    // 创建Session设置
    LastSessionSettings = MakeShareable(new FOnlineSessionSettings());
    LastSessionSettings->NumPublicConnections = NumPublicConnections;
    LastSessionSettings->bIsLANMatch = bIsLanMatch;
    LastSessionSettings->bShouldAdvertise = true;
    LastSessionSettings->bUsesPresence = true;
    LastSessionSettings->bUseLobbiesIfAvailable = true;

    // 发起异步创建
    const ULocalPlayer* LocalPlayer = GetWorld()->GetFirstLocalPlayerFromController();
    if (!SessionInterface->CreateSession(*LocalPlayer->GetPreferredUniqueNetId(), SessionName, *LastSessionSettings))
    {
        // 创建失败立即回调
        MultiplayerOnCreateSessionComplete.Broadcast(false);
    }
}

void UMultiplayerSessionsSubsystem::OnDestroySessionComplete(FName SessionName, bool bWasSuccessful)
{
    // 广播给蓝图
    MultiplayerOnDestroySessionComplete.Broadcast(bWasSuccessful);

    // 关键: 如果有缓存参数,重新创建Session
    if (bWasSuccessful && LastNumPublicConnections > 0)
    {
        CreateSession(SessionName, LastNumPublicConnections, bLastIsLanMatch);
        LastNumPublicConnections = 0;  // 清除缓存
    }
}

EOnlineSessionState::Type UMultiplayerSessionsSubsystem::GetSessionState(FName SessionName)
{
    if (!SessionInterface.IsValid())
    {
        return EOnlineSessionState::NoSession;
    }
    return SessionInterface->GetSessionState(SessionName);
```

## 6. 设计决策理由

### 为什么Hub必须单人?

**问题**: 如果在线模式允许进入Hub会怎样?

**分析**:
- Hub中有另一个主角NPC(玩家存档中的另一角色)
- 如果玩家A(男)和玩家B(女)联机进入Hub:
  - 玩家A的Hub应显示女性NPC(来自A的存档)
  - 玩家B的Hub应显示男性NPC(来自B的存档)
  - 但Listen-Server架构下Hub是共享的单一地图实例
  - 无法同时满足两个玩家的不同NPC需求

**结论**: Hub必须单人,在线玩家使用独立的Lobby Level进行匹配。

### 为什么Lobby必须是Level而不是Widget?

**问题**: 能否用Widget实现Lobby UI,不创建独立Level?

**分析**:
- ServerTravel需要目标地图路径: `GetWorld()->ServerTravel("/Game/Maps/Lobby?listen")`
- 从Dungeon返回时必须有地图可返回
- Widget无法作为ServerTravel的目标
- 如果返回MainMenu,则DestroySession → 解散房间 → 无法继续组队

**结论**: Lobby必须是独立Level,支持Dungeon完成后Seamless Travel回来继续组队。

### 为什么删除MainMenu的角色定制?

**问题**: 为什么不在MainMenu做角色外观定制?

**分析**:
- MainMenu是Hard Travel进入,没有ASC和Character实例
- 定制需要预览效果,需要实际加载Character Mesh
- 定制数据需要保存,但SaveGame尚未选择
- 用户可能只是想预览不同存档,不应触发修改

**结论**: 角色定制移至Hub,在那里已有完整的Character实例和ASC,定制后立即保存。

### 为什么不在运行时移除AttributeSet?

**问题**: 为什么不在退出Dungeon时移除CombatAttributeSet?

**技术风险**:
```cpp
//  危险操作
ASC->RemoveSpawnedAttribute(CombatAttributeSet);

// 可能导致的问题:
1. 如果有Effect正在引用CombatAttributeSet的属性 → 崩溃
2. 如果有Gameplay Cue正在播放 → 崩溃
3. 网络复制可能还在传输属性数据 → 不同步
4. Blueprint可能缓存了AttributeSet引用 → 野指针
```

**安全做法**:
- 只清理Effect和Ability
- 重置属性值到初始状态
- AttributeSet保留但不活跃

### 为什么SaveInfo和SaveGame分离?

**问题**: 为什么不直接加载所有SaveGame?

**性能分析**:
- 假设3个存档,每个SaveGame 500KB
- MainMenu启动时加载全部: 1.5MB + 反序列化时间
- SaveInfo只包含元数据: 每个槽位 <1KB,总计 <10KB

**用户体验**:
- MainMenu启动必须快速(< 1秒)
- SaveInfo同步加载无感知
- 完整SaveGame异步加载,仅在选择后进行

**结论**: 分离模式兼顾性能和体验,已在SaveGameSubsystem中实现。

### 为什么分屏只在Dungeon启用?

**问题**: 为什么不在Hub也支持分屏?

**设计原因**:
1. **Hub是个人空间**: 玩家1在定制外观时,玩家2无事可做
2. **性能考虑**: 分屏渲染开销大,Hub作为休息区不需要
3. **对标游戏**: 《双人成行》也是仅战斗关卡分屏,过场单人
4. **ASC复杂度**: 两个本地玩家共享同一存档的不同角色,状态同步复杂

**结论**: 分屏仅作为Dungeon的合作战斗模式,Hub保持单人体验。

## 9. 总结

本文档记录了从需求分析到技术方案的完整决策过程,包括:

**核心成果**:
1. 确立了单一Listen-Server架构统一三种游戏模式
2. 设计了Hub(单人) / Lobby(在线) / Dungeon(战斗)三级流程
3. 解决了Session生命周期管理的关键问题
4. 实现了ASC分层架构和战斗状态清理方案
5. 确认了SaveInfo/SaveGame分离模式已实现

**关键技术点**:
- Session残留检查和自动清理
- Seamless Travel配置和PlayerState持久化
- ASC动态加载和Effect清理
- SaveGame双主角数据结构扩展
- 本地分屏的动态启用/禁用

**设计原则**:
- 技术决策必须有明确的技术限制依据
- 优先使用引擎已有机制(Seamless Travel, ASC)
- 性能和用户体验平衡(SaveInfo分离)
- 代码复用最大化(Listen-Server统一架构)
