# 2025-11-14 库存系统集成方案记录

## 背景
- GameDesign v7.0/v7.2 引入材料、徽章、设计图、金币、消耗品与 Hub 制作循环，现有 `UCombatComponent` 只有 3 个武器槽，无法承载持久背包。
- 现阶段弹药预测（`ARangedWeaponInstance::PredictedAmmo`）已稳定，但备弹、材料、制作条件仍缺少统一的数据源。
- 用户在 Docs/ExampleProjectCode 中提供了 Lyra 的 Inventory/TagStack 源码，允许我们在本地创建任务包并交接给 Claude Code。

## 研究结论
1. **需求拆解**  
   - 材料系统（军用合金/徽章/设计图/碎片/金币）需要堆叠存储、自动拾取、掉落视觉与 Hub UI。  
   - 制作系统需要实时检查资源并消耗（武器：徽章+图纸+合金+金币；服装：碎片+合金+金币+徽章）。  
   - 背包必须与 Quickbar、GAS Ability Cost、任务/成就系统联动，并支持持久化。
2. **方案比较**  
   - 继续扩展 `UCombatComponent` 成熟悉  inventory 会导致大量重复造轮子（FastArray、预测、TagStack、AbilityCost）。  
   - Lyra 已提供 `InventoryManagerComponent + InventoryItemInstance + GameplayTagStack`，可直接满足堆叠、复制、TagCost、子对象复制需求。
3. **决定**  
   - 复用 Lyra 架构，命名为 `ShootInventory*` 系列，`UCombatComponent` 只对 Quickbar 可装备项负责。  
   - 材料/货币使用 TagStack（例：`Inventory.Material.MilitaryAlloy`），GAS Cost 可重用 Lyra 的 `AbilityCost_ItemTagStack` 逻辑。  
   - 制作系统通过 InventoryManager API 扣减资源并产出 ItemInstance，再驱动武器/服装系统。
