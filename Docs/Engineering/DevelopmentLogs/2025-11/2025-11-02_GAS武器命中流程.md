# GAS武器命中流程对齐

日期：2025-11-02
负责人：AI
状态：已完成

## 背景

对齐Lyra的武器命中流程，确保命中型武器和投射物武器使用正确的GAS模式。

## 任务描述

目标：
- 命中型武器（步枪/狙击/霰弹）对齐Lyra的TargetData流程
- 投射物武器（火箭/榴弹）使用独立的Actor同步流程
- 明确两种流程的边界和使用场景

## 实现分析

命中型武器流程（Hitscan）：
```
客户端：
1. UShootGameplayAbility_Weapon_Fire激活
2. StartRangedWeaponTargeting（预测窗口）
3. 本地射线检测（AHitscanWeaponInstance::TraceBulletsInCartridge）
4. 生成TargetData
5. ServerSetReplicatedTargetData发送到服务器

服务器：
1. 接收TargetData
2. 验证命中
3. 应用伤害GameplayEffect
4. 广播GameplayCue
```

投射物武器流程（Projectile）：
```
客户端：
1. UShootGA_Weapon_Fire_Projectile激活
2. 预测表现（可选）

服务器：
1. 生成AShootProjectileBase Actor
2. 投射物飞行（UProjectileMovementComponent）
3. OnHit回调
4. ApplyRadialDamage（GameplayEffect + SetByCaller）
5. ExecuteGameplayCue广播爆炸表现

客户端：
1. 接收投射物Actor复制
2. 播放飞行表现
3. 接收GameplayCue
4. 播放爆炸表现
```

## 设计决策

是否需要统一成单一流程？
- 答案：不需要
- 理由：
  - 命中型已经对齐Lyra的TargetData模式
  - 投射物走Actor同步更符合原设计
  - 两种武器的物理表现本质不同
  - 只有在需要导引或预测命中点时，才考虑给投射物能力额外加TargetData

## TargetData.UniqueId处理

当前状态：
- UniqueId固定为0
- 功能正常，但无法支持命中重播

未来扩展（如需要）：
- 在AHitscanWeaponInstance维护自增FireId
- 附带到TargetData.UniqueId
- 服务器可用于验证或重播
- 其他逻辑无需改动

实现示例：
```cpp
// AHitscanWeaponInstance.h
private:
    int32 FireSequenceId = 0;

// AHitscanWeaponInstance.cpp
void AHitscanWeaponInstance::TraceBulletsInCartridge(...)
{
    TargetData->UniqueId = ++FireSequenceId;
    // ... 其他逻辑
}
```

## 后续注意事项

命中重播/验证：
- 只需增设FireId，不必重写Ability
- 在服务器端验证TargetData.UniqueId即可

准星UI：
- 结合AHitscanWeaponInstance的散布数据
- 参考Druid/Blaster的"客户端先扣弹、服务器同步矫正"方案

投射物校验：
- 投射物默认不发送TargetData
- 普通爆炸武器保持现状（命中同步成本最低）
- 如需锁定/预测命中点，可在Ability侧补充TargetData

架构分层：
- 命中武器：StartRangedWeaponTargeting -> TargetData -> 服务器验证
- 投射物武器：Ability生成投射物 -> 投射物在服务器命中
- 文档标注"投射物默认不发送TargetData"
