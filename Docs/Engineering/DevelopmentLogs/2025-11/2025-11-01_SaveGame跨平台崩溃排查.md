# SaveGame跨平台崩溃排查

日期：2025-11-01
负责人：AI
状态：已解决

## 背景

在macOS编辑器PIE模式下调用SaveGame序列化时发生崩溃，而Windows环境表现正常。

## 问题描述

现象：
- 调用链：AShootGameModeBase::RetrieveInGameSaveData() -> USaveGameSubsystem::LoadPlayerSaveGame() -> UGameplayStatics::SaveGameToSlot(SaveInfoData, SaveInfoSlotName, 0)
- 崩溃位置：UObjectBaseUtility::GetPathName
- Windows环境：偶发看似正常
- macOS环境：必现崩溃

调用栈摘要：
- 崩溃发生于SaveGame序列化流程
- 由ObjectProperty序列化触发
- 日志警告：ObjectProperty FSaveSlotItem::SaveSlotImage is not initialized properly

## 排查过程

第一步：检查日志
- 发现：ObjectProperty FSaveSlotItem::SaveSlotImage is not initialized properly 警告多次出现
- 定位：FSaveSlotItem结构体中的SaveSlotImage成员

第二步：检查FSaveSlotItem定义
```cpp
USTRUCT()
struct FSaveSlotItem
{
    GENERATED_BODY()

    UPROPERTY()
    FString SlotName;

    UPROPERTY()
    int32 SlotIndex;

    UPROPERTY()
    FString SlotSaveTime;

    UPROPERTY()
    UTexture2D* SaveSlotImage;  // 裸指针！
};
```

发现问题：
- SaveSlotImage是UTexture2D裸指针
- SaveGame序列化不允许写入原生UObject指针
- Windows上堆内存常被清零，所以偶发看似正常
- macOS上随机指针被当作有效UObject路径解析，在GetPathName阶段崩溃

第三步：验证根因
- 开启LogClass、LogSerialization日志
- 确认序列化时尝试写入裸指针
- 跨平台内存管理差异导致表现不同

## 解决方案

将裸指针改为软引用：

```cpp
USTRUCT()
struct FSaveSlotItem
{
    GENERATED_BODY()

    UPROPERTY()
    FString SlotName;

    UPROPERTY()
    int32 SlotIndex = 0;

    UPROPERTY()
    FString SlotSaveTime;

    UPROPERTY()
    TSoftObjectPtr<UTexture2D> SaveSlotImage;  // 改为软引用

    FSaveSlotItem()
        : SlotIndex(0)
    {}
};
```

使用软引用的加载代码：
```cpp
if (Slot.SaveSlotImage.IsValid())
{
    UTexture2D* Texture = Slot.SaveSlotImage.Get(); // 软引用已加载
}
else if (Slot.SaveSlotImage.IsNull() == false)
{
    FStreamableManager& Streamable = UAssetManager::GetStreamableManager();
    Streamable.RequestAsyncLoad(Slot.SaveSlotImage.ToSoftObjectPath(),
        FStreamableDelegate::CreateLambda([WeakRef = Slot.SaveSlotImage]()
        {
            if (WeakRef.IsValid())
            {
                UTexture2D* LoadedTexture = WeakRef.Get();
                // TODO: 使用LoadedTexture
            }
        }));
}
```
