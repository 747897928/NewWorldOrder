# 开发日志 Development Logs

## 目的

记录开发过程中的详细排查过程、决策推演、试错记录。

与技术笔记的区别：
- 开发日志：详细的时间线记录，包含完整上下文和推理过程
- 技术笔记：从日志中提炼的知识点，结构化且可独立理解

## 组织方式

按月归档：
```
DevelopmentLogs/
├── 2025-11/
│   ├── 2025-11-01_SaveGame跨平台崩溃排查.md
│   ├── 2025-11-02_武器实例分层改造.md
│   └── 2025-11-06_文档体系重构.md
└── 2025-12/
    └── ...
```

## 日志模板

```markdown
# 问题/任务标题

日期：YYYY-MM-DD
负责人：用户/AI
状态：进行中/已解决/已归档

## 背景

为什么需要做这件事

## 问题描述

详细描述遇到的问题或需要实现的功能

## 排查过程

1. 第一步尝试
   - 结果：...
   - 发现：...

2. 第二步尝试
   - 结果：...
   - 发现：...

## 解决方案

最终采用的方案及原因

## 代码变更

涉及的文件和关键代码

## 经验教训

从这次经验中学到的知识点（应提炼到Notes/）

## 相关链接

- 相关技术笔记
- 相关ADR
- 相关Commit
```

## AI使用指南

新Session读取策略：
- 不主动读取DevelopmentLogs（除非用户要求）
- 优先读取Notes/INDEX.md获取知识
- 只在需要了解历史决策背景时读取对应日志

记录时机：
- 完成复杂问题排查后
- 实现重要功能后
- 发现重要Bug并修复后

记录后操作：
- 提炼核心知识点到Notes/对应分类
- 更新Notes/INDEX.md
- 如有架构决策，创建ADR
