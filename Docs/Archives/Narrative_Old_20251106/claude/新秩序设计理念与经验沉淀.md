## 1. 核心设计哲学

### 1.1 机制产难度，不靠数值堆叠

原则： 难度应该来自敌人行为、组合、节奏和战术挑战，而不是简单地把HP乘以系数。

具体实践：

- 低难度：游荡者单线进攻，间隔3秒
- 中难度：游荡者 + 猎手混编，2方向夹击
- 高难度：游荡者 + 猎手 + 缠绕者，3方向 + 拉人机制

不这样做：

- 错误示范：高难度游荡者HP从150变成300
- 问题：破坏了真实系手感，TTK从0.5秒变成1秒，武器失去打击感

为什么重要：

- 保持武器手感一致性
- 让玩家感受到的是战术压力而非数值碾压
- 可重复游玩性更高（技巧提升有意义）

------

### 1.2 真实系 + 快TTK统一

原则： 普通体型敌人实战TTK维持在0.3-0.5秒，通过密度、夹角、穿插维持压力。

设计锚点：

- 游荡者HP 150作为基准
- AR（30伤害，600RPM）：5发 = 0.4秒理论，0.6秒实战
- 力量30玩家：4发 = 0.3秒理论，0.5秒实战

为什么这样设计：

- 真实系射击的核心是"打得死"
- 快TTK让每一发子弹都有价值
- 避免"子弹海绵"破坏沉浸感

配套机制：

- 特殊敌人用DR（伤害减免）而非高HP
- 吞噬者：600HP + 前扇面DR50% = 等效1200HP
- 装甲士兵：500HP + 正面DR60% = 等效1250HP

------

### 1.3 成长不是通胀

原则： 升级是工具解锁 + 小幅补偿，不是战力翻倍。

数值目标：

- Lv1到Lv30总战力提升：+35-45%
- 纯DPS提升：+15-20%
- 其余提升来自工具解锁（技能槽、被动槽）

设计逻辑：

- 属性系统：前期高收益，后期递减
  - 力量前10点 +2%/点，后10点 +1%/点
  - 体力前10点 +10HP/点，后10点 +4HP/点
- 技能数值固定，不吃属性（易平衡）
- 被动做成长变化（改变机制而非堆数字）

反例（为什么不这样做）：

- 错误：Lv30伤害是Lv1的3倍
- 问题：后期副本必须把敌人HP乘以3，前期副本变得毫无挑战

------

### 1.4 技能数值固定，被动做成长

原则： 主动技能不吃属性点，被动技能改变机制（刷新、传导、延时、范围）。

设计示例：

战术标记（主动技能）：

- 基础：标记敌人，团队伤害 +25%，持续5秒
- 数值永远固定（不管你力量多少，都是 +25%）

标记猎手（被动技能Lv3）：

- 改变机制：击杀被标记敌人刷新充能
- 从"2次标记"变成"理论无限标记"

为什么这样设计：

- 主动技能易于平衡（数值固定）
- 被动技能带来Build差异化（刷新流、传导流）
- 避免"属性点堆到某个技能"的畸形Build

------

### 1.5 充能制 + 护栏反滥用

原则： 强力机制用充能制限制，CDR（冷却缩减）不影响充能恢复。

充能制技能：

- 战术翻滚：3充能，12秒/充
- 战术超载（大招）：充能制，8秒基础 + 击杀延长最多16秒
- 战术标记：2充能，15秒/充，但击杀返还充能（通过被动）

护栏机制：

- 标记传导（被动）：2秒ICD（内部冷却）防止无限链
- 分裂弹（被动）：全局同时存在上限5个分裂弹
- 医疗链式（被动）：最多跳3次，总治疗量预算固定

为什么需要护栏：

- 防止滥用（无限循环）
- 控制性能开销（AOE/链式机制）
- 保持游戏节奏（不能永远无敌翻滚）

------

### 1.6 PPS软自适应只换波表

原则： 不改敌人HP/DR，只换波表（Low/Med/High）以适应每秒PPS（玩家战力）。

Director系统：

- Host评估当前PPS（每秒击杀数）
- 根据PPS选择波表档位：
  - Low：1波5个，间隔5秒
  - Med：1波8个，间隔4秒
  - High：1波12个，间隔3秒

为什么不改HP：

- 保持TTK手感统一
- 避免"越强越打不动"的反馈
- 让玩家感受到的是"敌人更多更快"而非"敌人更肉"

------

### 1.7 感觉优先于纸面

原则： 如果玩家反馈"来不及反应"，先调攻击频率/前摇，保持DPS常数。

设计示例：

猎手初版：

- 伤害30，攻击间隔1秒
- DPS = 30
- 玩家反馈："太快了，根本来不及反应"

猎手修正版：

- 伤害45，攻击间隔1.5秒
- DPS = 30（保持不变）
- 玩家反馈："能看到他扑过来，有反应时间"

为什么这样调整：

- 纸面DPS不变（难度没降低）
- 体感友好（给了反应窗口）
- 鼓励技巧（翻滚躲闪有意义）

## 2. 双主角差异化设计

### 2.1 核心定位差异

陈浩宇（男主）：

- 身份：前龙旗特种兵
- 定位：输出/破坏/前线
- 技能风格：暴力、直接、高输出

沈芸皖（女主）：

- 身份：前复兴集团研究员
- 定位：治疗/支援/侦察
- 技能风格：保护、辅助、策略

------

### 2.2 初始属性的叙事性设计

男主初始属性（Lv1）：

- 力量4，体力4，敏捷1，感知1

为什么敏捷低：

- 叙事理由：曾受重伤，机动能力受限
- 设计理由：强迫玩家投点到敏捷（制造成长感）
- 差异化：女主敏捷4，形成对比

为什么感知低：

- 叙事理由：擅长对抗人类，但对末日异变体缺乏经验
- 设计理由：让女主的高感知（侦察定位）更有价值
- 配合机制：男主需要女主的战术扫描技能

女主初始属性（Lv1）：

- 力量1，体力2，敏捷4，感知3

为什么力量低：

- 叙事理由：研究员，没有军事训练
- 设计理由：女主依赖技能和策略而非纯输出

为什么敏捷高：

- 叙事理由：科研工作养成的敏锐反应
- 设计理由：配合支援定位（需要灵活走位）

------

### 2.3 技能动画的性格表达

战术翻滚对比：

男主动画：

- "经过严格训练的战术机动，保持武器姿态的同时快速脱离危险"
- 表现：翻滚流畅，武器始终指向前方，落地立即开火
- 传达：专业、训练有素

女主动画：

- "在危机中激发的本能反应，虽不如军人优雅，但同样有效"
- 表现：翻滚略显慌乱，武器姿态不稳，但同样达到目的
- 传达：非战斗人员的求生本能

为什么这样设计：

- 相同功能（0.4秒无敌）
- 不同表现（性格差异）
- 增强代入感（玩家感受到角色不同）

------

### 2.4 遮蔽机制的独占性设计

核心理念： 遮蔽的核心是"让女主安全救人"，不是"给所有人保命"。

初期错误方案（已废弃）：

- 隐匿治疗：给所有队友遮蔽效果
- 问题：女主失去独特性，所有人都能安全

最终方案： 救援掩护（女主专属）：

- 只有女主进入隐匿状态6秒
- 隐匿期间移速 +30%
- 救援倒地队友速度 +100%（3秒变1.5秒）
- 救起队友后，队友获得3秒无敌

为什么这样改：

- 保持女主独特性（只有她能隐匿）
- 专门用于救援场景（定向设计）
- 与WWZ的Stim Pistol区分：
  - WWZ：给队友遮蔽
  - 我们：女主自己隐匿去救人

## 3. 技能设计方法论

### 3.1 技能设计的四个维度

每个技能必须明确回答：

1. 机制独特性：
   - 这个技能做什么？
   - 和其他技能有什么区别？
2. 使用场景：
   - 什么时候用？
   - 什么情况下最有价值？
3. Build协同：
   - 和哪些被动/技能配合？
   - 形成什么Build？
4. 反滥用设计：
   - 有什么限制？
   - 为什么不能无限用？

------

### 3.2 技能设计案例分析：生物抑制剂

初版设计：

- 投掷瓶子，减速敌人60%，持续8秒
- 冷却25秒

问题诊断：

为什么玩家不会选：

- 收益不明显：减速60%听起来很强，但对单个精英意义不大
- 没有独特价值：男主的震撼手雷已经有控制 + 易伤，生物抑制剂只是"弱化版"
- 不符合女主定位：女主是辅助，但这个技能既不加血也不加护盾，只是"软控"

设计思路转折点： 你提出了一个非常好的设计思路："技能吃外部环境的红利"

最终方案（感染抑制剂）：

- 投掷瓶子，AOE范围对队友清除负面效果 + 免疫5秒
- 冷却25秒
- 配合机制：
  - 清除缠绕者的拉拽状态
  - 免疫干扰者的"混乱云"
  - 免疫吞噬者的"感染减速"

为什么这样改好：

- 独特价值：唯一能清除特殊负面的技能
- 吃环境红利：
  - 对普通敌人：价值一般（可以不带）
  - 对特殊敌人：价值极高（必带）
- 符合女主定位：保护队友免受异常状态

设计教训：

- 不要设计"数值型控制"（减速X%），很难平衡
- 设计"功能型解法"（清除/免疫），有明确价值

------

### 3.3 技能设计案例分析：战术无人机

设计挑战：

- 召唤物AI很难做
- 需要平衡"有用但不无敌"
- 要避免"放了就不管"的无脑玩法

解决方案：3模式 + 智能切换

模式1：治疗模式（默认）

- 跟随女主，每3秒治疗8%
- 场景：日常推进，持续回血

模式2：侦察模式（按E切换）

- 前飞侦察，标记敌人
- 场景：探路，提前预警

模式3：战斗模式（自动触发）

- 女主血量 < 30%时自动切换
- 治疗间隔1.5秒（双倍频率）
- 场景：紧急救命

为什么这样设计好：

- 有手动操作空间（侦察模式）
- 有自动应急机制（战斗模式）
- 不会无脑强（治疗量8%适中）

设计教训：

- 召唤物不要"完全自动"（无聊）
- 也不要"完全手动"（复杂）
- 给玩家"有意义的选择"（模式切换）

------

### 3.4 技能设计案例分析：战术超载（男主大招）

设计目标：

- 让男主有"火力压制"的高光时刻
- 不能无限续（需要击杀延长）
- 鼓励进攻而非防守

最终机制：

- 基础持续8秒
- 击杀延长0.5秒，上限+8秒（总计16秒）
- 射击不消耗弹药 + 射速 +30%

关键设计点：

充能制而非冷却制：

- 为什么：防止"攒大招一波流"
- 充能获取：击杀精英/完成目标/时间推进

击杀延长机制：

- 为什么：鼓励进攻
- 数值设计：
  - 0.5秒/击杀 = 需要16次击杀才能达到上限
  - 配合射速 +30% + 无限弹药 = 可以达成

上限锁死（+8秒）：

- 为什么：防止"无限延长"
- 设计哲学：强力时刻应该是"短暂的高光"，不是"永久开挂"

与极限火力（隐藏大招）的区别：

- 战术超载：可延长，适合清群
- 极限火力：固定6秒，但射速x2 + 无扩散，适合秒Boss

## 4. 数值平衡原则

### 4.1 属性递减设计

原则： 前期高收益，后期递减，避免"全堆一项"。

体力递减曲线：

- 0-10点：+10HP/点（100 → 200HP，+100%）
- 11-20点：+6HP/点（200 → 260HP，+30%）
- 21-30点：+4HP/点（260 → 300HP，+15%）

为什么递减：

- 前期投入回报高（鼓励平衡发展）
- 后期专精收益递减（避免极端Build）
- 30点体力玩家比10点体力玩家只多50%血量，而非3倍

力量递减曲线：

- 0-10点：+2%/点（+20%总伤害）
- 11-20点：+1.5%/点（+15%总伤害）
- 21-30点：+1%/点（+10%总伤害）
- 30点力量 = +45%伤害（不是+100%）

------

### 4.2 护盾系统的叠加设计

基础护盾：

- 任何治疗超过MaxHP时，转化为护盾
- 基础上限：25% MaxHP

体力加成：

- +1.5%/点
- 30点体力：25% + 45% = 70% MaxHP

为什么这样设计：

- 体力玩家有明显收益（70% vs 25%）
- 但不会失控（不是200%）
- 配合女主治疗技能（护盾发生器直接给40%）

------

### 4.3 弱点倍率的非线性设计

基础倍率：

- x2.0（所有角色初始）

感知加成：

- +1%/点
- 30点感知：x2.0 → x2.3

每10点感知的特殊效果：

- 10点：连续3次弱点命中，下一发 +50%
- 20点：连续3次弱点命中，下一发 +100%
- 30点：连续3次弱点命中，下一发 +150%

为什么这样设计：

- 基础收益线性（+1%/点）
- 但有突破点（每10点的特殊效果）
- 奖励精准玩家（连续弱点命中）
- 配合男主的破甲射击技能（弱点倍率 +30%）

------

### 4.4 敌人HP的锚点设计

设计锚点： 游荡者HP = 150

为什么选150：

- AR（30伤害，600RPM）：5发 = 0.4秒理论
- 实战命中率80%：6发 = 0.5秒
- 力量30玩家（40.5伤害）：4发 = 0.3秒

其他敌人HP按比例：

- 猎手：120（80%游荡者，移动快）
- 爬行者：100（66%游荡者，体型小）
- 缠绕者：120（特殊机制补偿）
- 干扰者：100（飞行单位）

大型敌人不用高HP：

- 吞噬者：600HP + DR50%（前扇面）= 等效1200HP
- 装甲士兵：500HP + DR60%（正面）= 等效1250HP

为什么用DR而非高HP：

- 保持TTK手感一致
- 鼓励侧面/背面攻击（破DR）
- 配合男主破甲技能（护甲-50%）

------

### 4.5 被动技能的预算管理

原则： 每个被动Lv3的强度应该让玩家"想要但不能全要"。

预算系统：

- 4个被动槽
- 每个被动Lv1/2/3需要1/2/5点（总8点）
- 满级单个被动：8点
- 4个被动槽 x 8点 = 32点
- 但总共只有29点技能点

为什么这样设计：

- 强迫选择（不能全满）
- Build差异化（不同玩家选择不同被动）
- 配合重置系统（允许试错）

强度校准：

- Lv1被动：锦上添花（+5-10%效果）
- Lv2被动：明显提升（+15-20%效果）
- Lv3被动：改变玩法（质变，不是量变）

示例：

标记猎手（男主被动）：

- Lv1：战术标记持续时间 +2秒（5秒 → 7秒）
- Lv2：标记传导，击杀传导到5m内敌人（2秒ICD）
- Lv3：击杀被标记敌人刷新充能

为什么Lv3是质变：

- 从"2次标记"变成"理论无限标记"
- 前提是你能稳定击杀（技巧要求）
- 配合标记传导（Lv2），形成"标记流"Build

------

## 5. 独立开发者的取舍

### 5.1 锁定库规模

原则： 少而精，每个内容都要有独特价值。

技能池：

- 男主8个技能（6普通 + 2大招）
- 女主8个技能（6普通 + 2大招）
- 不做：20个技能池（平衡噩梦）

敌人族谱：

- 5个基础敌人（游荡者/猎手/爬行者/缠绕者/干扰者）
- 2个大型敌人（吞噬者/装甲士兵）
- 每章1-2个特色变体
- 不做：30种敌人（美术成本爆炸）

副本设计：

- 10个主线章节
- 每章5-8分钟
- 每章1-2个特色机制
- 不做：开放世界（关卡设计成本不可控）

为什么这样取舍：

- 独立开发者资源有限
- 宁可10个高质量，不要50个低质量
- 每个内容都要有独特价值

------

### 5.2 Lv20质变做改装槽

原则： 用系统解锁代替数值膨胀，兑现"升级有盼头"。

设计方案：

- Lv20解锁武器改装系统
- 改装槽：枪口/握把/弹夹/瞄具（4个槽）
- 每个配件提供小幅数值 + 机制改变

示例配件：

穿甲弹夹：

- 护甲穿透 +15%
- 弹夹容量 -10%
- 独特机制：穿透1个敌人（配合人群）

高速弹夹：

- 换弹速度 +30%
- 弹夹容量 -15%
- 独特机制：换弹时移速不降低

为什么这样设计：

- Lv20是中期节点，需要明确奖励
- 改装系统增加Build深度
- 但不改变核心平衡（都是微调）

开发成本：

- 配件系统：数值修改器（已有GAS）
- 不需要新美术（材质球变色即可）
- CSV配置驱动（易于平衡）

------

### 5.3 Listen Server友好设计

原则： 减少状态广播，避免高频数值闪烁。

技术限制：

- Listen Server = Host是玩家
- Host CPU/带宽有限
- 不能像Dedicated Server那样高频同步

设计适配：

技能设计：

- 避免"每帧修改数值"的技能
- 用离散事件（标记/眩晕/治疗）而非连续Buff
- 标记系统：广播1次，客户端本地计算伤害加成

无人机AI：

- 服务端控制行为
- 客户端预测位置（避免抖动）
- 治疗事件服务端确认（避免作弊）

敌人同步：

- 位置：10Hz同步（每100ms）
- HP：事件驱动（受伤时同步）
- 死亡：立即广播（关键事件）

------

### 5.4 CSV一键换参

原则： 策略不改，参数可热调。

数据驱动设计：

Enemies.csv：

```
ID,Name,HP,Damage,MoveSpeed,AttackRate,DR_Front
E_Wanderer,游荡者,150,20,300,2.0,0
E_Hunter,猎手,120,30,450,1.5,0
E_Devourer,吞噬者,600,40,250,3.0,0.5
```

修改游荡者HP：

- 改CSV：150 → 120
- 重启游戏即生效
- 不需要改代码，不需要重新编译

为什么这样设计：

- 快速迭代平衡
- 避免"改个数字要等1小时编译"
- 支持运营期热更新

适用范围：

- 敌人数值：HP/伤害/移速
- 武器数值：伤害/射速/弹夹
- 技能数值：冷却/持续/范围
- 不适用：机制改变（需要改代码）

------

### 5.5 把强度关进机制笼子

原则： 用充能/ICD/上限/矩阵管理强力机制，而非简单地"降低数值"。

示例1：标记传导

如果不加限制：

- 击杀1个敌人 → 传导5m内所有敌人
- 5个敌人全被标记 → 全被击杀 → 传导更多
- 结果：无限链，整个地图被标记

加入ICD（内部冷却）：

- 传导2秒ICD
- 2秒内只能传导1次
- 结果：可控，但仍然强力

示例2：分裂弹被动

如果不加限制：

- 每发子弹分裂2发
- 分裂子弹再分裂
- 结果：指数爆炸，性能崩溃

加入全局上限：

- 同时存在最多5个分裂弹
- 新的分裂弹会替换最旧的
- 结果：可控，适合清群

示例3：翻滚无敌

如果不加限制：

- 翻滚0.4秒无敌
- 无冷却
- 结果：连续翻滚，永远无敌

加入充能制：

- 3充能，12秒/充
- CDR不影响充能恢复
- 结果：需要管理资源，不能无脑用

设计哲学：

- 不要害怕设计强力机制
- 用"笼子"（限制）而非"削弱"（降数值）
- 让玩家感受到强力，但要为此付出代价

## 6. 常见陷阱与避坑经验

### 6.1 陷阱：过度复杂的技能描述

错误示范：

战术标记： "标记敌人，使其受到的伤害提高25%，持续5秒。如果目标在标记期间被击杀，则标记会传导至5米范围内的其他敌人（冷却2秒）。如果玩家的感知属性大于等于20，则标记持续时间额外延长30%。击杀被标记的敌人有15%概率刷新一次充能。"

问题：

- 一个技能包含4个机制
- 玩家记不住
- 调试困难

正确做法：

主动技能：战术标记

- 标记敌人，团队伤害 +25%，持续5秒
- 2充能，15秒/充
- （简单、明确）

被动技能Lv2：标记传导

- 击杀被标记敌人，传导5m内敌人（2秒ICD）

被动技能Lv3：标记猎手

- 击杀被标记敌人，刷新充能

教训：

- 一个技能只做一件事
- 复杂性用被动技能分层
- 让玩家自己组合Build

------

### 6.2 陷阱："自解释代码"的谎言

错误观念： "好的代码不需要注释"

现实：

GAS系统示例：

```cpp
// 错误：无注释
void UMyAbility::ApplyDamage(float Value) {
    FGameplayEffectSpecHandle Spec = MakeOutgoingSpec();
    Spec.Data->SetSetByCallerMagnitude(FGameplayTag::RequestGameplayTag("Data.Damage"), Value);
    ApplyGameplayEffectSpecToTarget(Spec, Target);
}

// 正确：关键逻辑注释
void UMyAbility::ApplyDamage(float Value) {
    // 创建伤害GE的Spec Handle
    FGameplayEffectSpecHandle Spec = MakeOutgoingSpec();
    
    // 用SetByCaller方式传递伤害值，避免硬编码
    // Tag "Data.Damage" 在GE蓝图中配置为Magnitude的SetByCaller
    Spec.Data->SetSetByCallerMagnitude(
        FGameplayTag::RequestGameplayTag("Data.Damage"), 
        Value
    );
    
    // 应用到目标（会触发目标的伤害计算链）
    ApplyGameplayEffectSpecToTarget(Spec, Target);
}
```

教训（来自你的经验）：

- "我更习惯详细的注解，虽然会影响写代码的效率，但是可以让别人看懂自己的代码"
- "不能让别人看懂的代码那不是好代码"
- 3个月后回看代码，你就是"别人"

注释的平衡：

- 不要注释"i++"这种显而易见的
- 必须注释"为什么这样做"
- 必须注释"GAS的Tag/GE/GA之间的关联"

------

### 6.3 陷阱：过早优化

错误做法：

第一次实现战术标记：

- 先考虑性能
- 用Object Pool
- 用Custom Replication
- 写了500行代码
- 花了3天
- 然后发现设计要改

正确做法：

第一次实现战术标记：

- 先跑通逻辑
- 用最简单的方式（GAS的ApplyGameplayEffectToTarget）
- 50行代码
- 1小时完成
- 测试设计是否好玩
- 如果不好玩，改设计（成本低）
- 如果好玩，再考虑优化

教训：

- "过早优化是万恶之源"（Donald Knuth）
- 独立开发者先保证"能玩"，再优化"好玩"
- 性能问题等性能分析器告诉你了再说

------

### 6.4 陷阱：用属性加成平衡技能

错误做法：

战术超载（大招）：

- 基础持续8秒
- +力量x0.1秒
- 力量30玩家：持续11秒

问题：

- 力量30玩家比力量10玩家强37.5%
- 后期玩家变成"开挂"
- 平衡崩溃

正确做法：

战术超载（大招）：

- 持续8秒（固定）
- 击杀延长0.5秒（上限+8秒）
- 所有玩家都是8-16秒

为什么这样好：

- 数值固定，易平衡
- 延长机制鼓励进攻
- 力量高的玩家仍然有优势（输出高，更容易击杀延长）
- 但不会失控（上限锁死）

------

### 6.5 陷阱：忽视网络延迟的影响

错误做法：

翻滚无敌：

- 客户端：播放动画
- 服务端：0.4秒后设置无敌
- 结果：100ms延迟时，客户端看到翻滚了，但服务端还没确认，被打死

正确做法：

翻滚无敌：

- 客户端：立即播放动画 + 本地预测无敌
- 服务端：收到RPC后立即确认无敌
- 客户端：如果预测错误，回滚（极少发生）

技术实现：

- 用GAS的Prediction Key
- 客户端预测ApplyGameplayEffect（无敌Tag）
- 服务端确认或回滚

教训：

- Listen Server有延迟（Host除外）
- 关键体验（翻滚/治疗）必须客户端预测
- 不关键的（标记传导）可以服务端确认

------

### 6.6 陷阱：设计"纸面很强但实际不会用"的技能

错误示范：

生物抑制剂（初版）：

- 减速60%，持续8秒
- 纸面：很强的控制
- 实际：玩家不带

为什么不带：

- 对单个敌人：用枪打死更快
- 对群体：没有AOE价值（不如手雷）
- 没有独特场景：任何时候用都是"还行但不必要"

改进思路：

感染抑制剂（最终版）：

- 清除负面效果 + 免疫5秒
- 纸面：听起来普通
- 实际：特定场景必带

为什么会带：

- 对缠绕者：清除拉拽（独特价值）
- 对干扰者：免疫混乱云（独特价值）
- 对吞噬者：免疫感染减速（独特价值）

教训：

- 不要设计"全场景70分"的技能
- 设计"特定场景100分，其他场景0分"的技能
- 让玩家根据副本选择Build

------

## 7. 灵感与创新点记录

### 7.1 尸潮红利机制（未实现，但值得记录）

灵感来源： 你提出的"技能吃外部环境的红利"

设计草案：

尸潮状态：

- 当屏幕上敌人数量 > 15时，进入"尸潮"状态
- 尸潮期间，某些技能获得额外效果

示例技能：

破片手雷（假想技能）：

- 普通：爆炸伤害100，范围3m
- 尸潮红利：爆炸后生成6个破片，每个破片造成30伤害并弹射

为什么有趣：

- 鼓励进攻（在压力大的时候技能更强）
- 奖励冒险（不躲避反而更有利）
- 符合丧尸片的"险中求胜"氛围

为什么没实现：

- 需要额外的状态追踪（复杂度）
- 平衡困难（正常vs尸潮的数值差异）
- 可能作为未来DLC的特色机制

------

### 7.2 控制矩阵（已实现）

灵感来源： WWZ的控制免疫机制

设计问题：

- 如果精英也能被震撼手雷眩晕2秒，太容易
- 如果精英完全免疫控制，控制技能对精英无用

解决方案：

控制矩阵（Control Matrix）：

- 精英/Boss不进入硬控状态
- 但会"打断当前动作"
- 并受到"易伤"效果

实例：

吞噬者使用"吞噬攻击"（3秒前摇）：

- 普通打断：任何伤害打断
- 震撼手雷打断：打断 + 易伤30%，持续4秒

为什么这样好：

- 控制技能对精英仍然有用（打断 + 易伤）
- 但不会让精英变成"木桩"
- 奖励时机把握（打断高价值技能）

技术实现：

- 用GAS的GameplayTag
- 精英有"Control.Immune"Tag
- 但监听"Control.Interrupt"事件
- 触发打断动画 + ApplyGameplayEffect（易伤）

------

### 7.3 战术无人机的智能模式切换（已实现）

设计挑战：

- 召唤物要有"智能感"
- 但不能"聪明到玩家不需要操作"

解决方案：

3模式 + 自动应急：

- 默认：治疗模式（跟随）
- 手动：侦察模式（前飞）
- 自动：战斗模式（女主血量<30%触发）

为什么有智能感：

- 会根据女主血量自动切换紧急模式
- 战斗模式治疗频率翻倍（1.5秒/次）

为什么仍需操作：

- 侦察模式需要手动切换（E键）
- 战斗模式虽然自动触发，但只在危机时

教训：

- AI系统要"8分自动，2分手动"
- 让玩家感觉"AI在帮我"而非"AI替我玩"

------

### 7.4 充能制大招的击杀延长机制（已实现）

灵感来源： DOOM的"Glory Kill延长狂暴时间"

设计目标：

- 大招要有"高光时刻"的感觉
- 但不能"开了就躺赢"

战术超载（男主大招）：

- 基础8秒
- 击杀延长0.5秒
- 上限+8秒（总16秒）

为什么这样好：

- 鼓励进攻（躲起来不延长）
- 奖励技术（精准射击，更多击杀）
- 有明确上限（不会无限延长）

与其他游戏的区别：

- DOOM：击杀延长无上限（可以"永久狂暴"）
- 我们：击杀延长有上限（控制强度）

------

### 7.5 遮蔽机制的场景专精设计（已实现）

设计转折：

- 初版：遮蔽给所有人（WWZ式）
- 问题：女主失去独特性
- 最终：遮蔽只给女主，专门用于救援

救援掩护（女主E技能）：

- 女主隐匿6秒
- 救援速度x2
- 救起后队友3秒无敌

为什么这样好：

- 有明确使用场景（救人）
- 女主独占（独特性）
- 配合其他治疗技能（不是全能技能）

设计哲学：

- 不要设计"全场景都有用"的技能
- 设计"特定场景必须用"的技能
- 通过场景差异化技能价值

------

### 7.6 属性的叙事性设计（已实现）

设计理念： 属性不只是数字，也是角色的故事。

男主低敏捷的叙事：

- 数值：敏捷1（30%低于女主）
- 叙事：曾受重伤，膝盖和腰部有旧伤
- 玩法：需要投点补强或接受限制

男主低感知的叙事：

- 数值：感知1
- 叙事：军人训练针对人类，对异变体经验不足
- 玩法：需要女主的战术扫描辅助

女主低力量的叙事：

- 数值：力量1
- 叙事：研究员，缺乏军事训练
- 玩法：依赖技能而非纯输出

为什么这样设计好：

- 初始属性不是"对称平衡"（男4/4/1/1，女1/2/4/3）
- 每个低属性都有故事理由
- 玩家会自然地投点补强（制造成长感）

教训：

- 数值设计要有叙事支撑
- 不要为了"平衡"而牺牲"个性"

------

### 7.7 被动技能的"质变而非量变"设计（已实现）

设计原则： Lv3被动应该改变玩法，而非只是"+50%效果"。

示例：

标记猎手Lv3（男主被动）：

- 不是：标记伤害加成从+25%变成+50%
- 而是：击杀被标记敌人刷新充能（从"2次"变成"理论无限"）

医疗强化Lv3（女主被动）：

- 不是：治疗量从+20%变成+40%
- 而是：治疗跳3次（从"单体治疗"变成"群体治疗"）

分裂弹药Lv3（男主被动）：

- 不是：分裂伤害从30%变成60%
- 而是：分裂子弹再分裂1次（从"1分2"变成"1分4"）

为什么这样设计：

- Lv3被动8点投入（技能点总共29点）
- 必须有"值得"的感觉
- 质变让玩家感受到Build的独特性

教训：

- 数值堆叠是无聊的
- 机制改变是有趣的
- 让玩家为了某个Lv3被动设计整个Build

------

### 7.8 CSV驱动设计的灵活性（已实现）

设计哲学： 代码定义"怎么做"，数据定义"做什么"。

示例：

敌人数据（Enemies.csv）：

```
ID,HP,Damage,MoveSpeed,AttackRate
E_Wanderer,150,20,300,2.0
```

修改平衡：

- 不改代码
- 改CSV：HP 150 → 120
- 重启即生效

波表数据（WaveTable.csv）：

```
Chapter,Difficulty,Wave,EnemyID,Count,Interval
1,Low,1,E_Wanderer,5,5.0
1,High,1,E_Wanderer,12,3.0
```

修改难度：

- 不改代码
- 改CSV：Count和Interval
- 重启即生效

为什么这样重要：

- 独立开发者需要快速迭代
- 避免"改个数字等1小时编译"
- 支持运营期热更新（如果上线）

教训：

- 前期投入时间做数据驱动系统
- 后期省下10倍的平衡调整时间

## 结语

这份文档记录了我们在设计《新秩序》过程中的核心理念、关键决策、避坑经验和灵感火花。

核心原则回顾：

1. 机制产难度，不靠数值堆叠
2. 真实系 + 快TTK统一
3. 成长不是通胀
4. 技能数值固定，被动做成长
5. 充能制 + 护栏反滥用
6. PPS软自适应只换波表
7. 感觉优先于纸面

设计哲学：

- 少而精，每个内容都有独特价值
- 让玩家为难以选择而苦恼（Build深度）
- 用机制而非数值管理强度
- 数值要有叙事支撑
- 质变而非量变

给未来自己的建议：

- 当你想改某个数值时，先想想是不是机制设计的问题
- 当你觉得某个技能"纸面很强"时，想想实际场景
- 当你想加新内容时，先问"这个内容有独特价值吗"
- 当你忘记某个设计决策时，回来看这份文档
