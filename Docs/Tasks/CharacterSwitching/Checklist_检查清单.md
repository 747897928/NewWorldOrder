# 角色切换验收清单

版本：1.1
最后更新：2026-03-13
状态：可执行

## 目标
- 验证男主与女主换装数据相互独立。
- 验证角色切换结果可写入存档并在重进后恢复。
- 验证宿舍切换入口的长按流程在联机场景下可用。

## 预置条件
- 已完成 `WBP_CharacterSwitchHoldPanel` 蓝图接线。
- 角色切换站点或占位入口已放入宿舍场景并可交互。
- 当前分支代码已编译通过。

## 场景 A：基础长按切换流程
1. 进入宿舍，初始主角应为男主（无历史存档时）。
2. 靠近切换入口并按住交互键，确认进度条开始推进。
3. 在未读满前松开按键，确认进度条回落且主角不变。
4. 再次长按直到读满，切换到女主，显示成功结果。
5. 再次长按直到读满，切回男主，显示成功结果。

通过标准：
- 中途松手不发生切换。
- 读满后一定发生切换，且结果提示正确。
- 回落过程可见，不是瞬间硬清零。

## 场景 B：男女主换装独立
1. 保持男主，修改男主外观参数并保存一次（触发当前保存流程）。
2. 切到女主，确认女主初始外观与男主不同或为女主上次外观。
3. 修改女主外观参数并保存一次。
4. 切回男主，检查男主外观仍是步骤 1 的结果。
5. 再切回女主，检查女主外观仍是步骤 3 的结果。

通过标准：
- 男主与女主外观不会互相覆盖。
- 多次往返切换后外观保持稳定。

## 场景 C：QuickBar 独立
1. 男主状态下调整 QuickBar 并保存。
2. 切到女主，调整女主 QuickBar 并保存。
3. 男主/女主来回切换两次。

通过标准：
- 男主 QuickBar 始终保持男主配置。
- 女主 QuickBar 始终保持女主配置。

## 场景 D：存档恢复
1. 当前切到女主并保存。
2. 退出到主菜单，重新进入同一存档。
3. 观察当前主角与外观、QuickBar。
4. 再切到男主并保存，重复退出重进。

通过标准：
- `LastActiveGender` 生效，重进后主角与退出前一致。
- 对应主角的外观与 QuickBar 一并恢复。

## 场景 E：失败路径
1. 在非 Hub/安全区尝试切换。
2. 菜单长按过程中松手。
3. 世界入口当前按交互键后，在非法区域触发失败提示。

通过标准：
- 非法区域返回“仅可在Hub/安全区切换”。
- 菜单长按松手时进度回落且不发生切换。

## 排查顺序（失败时）
1. 看 `AShootPlayerController` 是否收到了 `OnCharacterSwitchHoldProgressChanged` 与 `OnCharacterSwitchResult`。
2. 看菜单入口是否正确绑定了 `IA_SwitchCharacter` 与 `UCommonActivatableWidget::InputMapping`。
3. 看 `AShootPlayerState::SwitchToCharacter` 是否返回 true。
4. 看 `ServerSetAppearanceTags` 是否被调用并触发外观更新。
5. 看 SaveGame 中 `MaleProtagonist`、`FemaleProtagonist`、`LastActiveGender` 是否更新。
