## 0. 文档状态

- 状态：调研阶段完成，进入实现前方案草稿。
- 更新时间：2026-09-14。
- 维护方式：玩法规则、现有 Unreal 代码事实和 Unity 参考证据分开记录。后续修改只更新受影响的章节。

## 2. 当前 Unreal 工程事实

### 2.1 Experience

当前 UShootExperienceDefinition 已有以下配置：

- HUD 根布局和 HUD 插槽片段。
- 男主和女主 AbilitySet。
- 公共 AbilitySet。
- 四槽 Match Skill 的 SkillLoadoutConfig。
- 默认相机视角、相机切换开关和游泳开关。

当前 Experience 定义没有感染规则、回合数量、回合阶段、初始僵尸数量、角色目录、死亡策略、重生策略、胜负策略、加入策略、逃亡阶段或奖励配置。

UShootExperienceManagerComponent 位于 GameState：

- 服务器设置并复制当前 Experience 的软对象路径。
- 本机同步加载定义并广播 Experience 已加载。
- 服务器给已有 PlayerState 补授予公共和当前性别 AbilitySet。
- Experience 卸载时先清理 Match Skill，再逆序撤销性别和公共 AbilitySet。
- HUD 使用目标 HUD 的 OwningPlayer 对应 LocalPlayer 推入 CommonUI 层并注册 UIExtension。

生化模式应继续使用这条生命周期。健康归零后的死亡或感染由 Experience 授予的响应 Ability 处理，回合裁决和地图阶段行为由模式 GameMode 处理，Experience 只声明组合内容。

### 2.2 GameMode 与 GameState

当前 AShootGameModeBase 已提供：

- InitGame 解析 Experience、地图和大厅 URL 参数。
- InitGameState 设置 Experience 和远征大厅组件。
- PostLogin 为 PlayerState 设置默认队伍 ID 1，并幂等补授予 Experience 能力。
- 玩家和敌人死亡后的通用重生入口。
- InitializeRoundForAll，服务器重置玩家和敌人的默认属性。
- 基于 Team Attitude 的友伤倍率。
- 击杀通知和玩家私有准星击杀反馈。

当前 GameStateBase 只有 ExperienceManagerComponent 和 ExpeditionLobbyComponent，ShootGameState 没有生化状态字段。

生化模式需要专用 GameMode 规则入口和 GameState 公开状态。GameMode 只在服务器做裁决，GameState 复制玩家需要知道的快照。

### 2.3 PlayerState、ASC 与 Pawn

AShootPlayerState 当前：

- 实现 ILyraTeamAgentInterface，MyTeamID 服务器写入并复制。
- 持有 PlayerState 上的 UShootAbilitySystemComponent 和 UShootAttributeSet。
- 持有 InventoryManager、ResourceInventory、SkillLoadout 和 RobotCompanion 组件。
- 以 GrantedHandles 分别管理 Experience 公共和当前性别 AbilitySet。
- 运行时切换男女主时只刷新性别 AbilitySet，不触碰公共 AbilitySet。
- 进入 Experience 时补授予，离开 Experience 时按来源完整回收。

AShootCharacter::InitAbilityActorInfo 把 PlayerState ASC 初始化为 Owner，当前 Pawn 初始化为 Avatar，然后让 Character 的 AbilitySystemComponent 和 AttributeSet 指向 PlayerState 上的对象。因此玩家重生或感染换 Pawn 时，PlayerState ASC 是持续能力和技能状态的主要归属。

AEnemyBotCharacter 使用自身 Character ASC，AI 的 Zombie AbilitySet 在 PossessedBy 中授予，在 UnPossessed 和 EndPlay 中按句柄回收。玩家和 AI 的 ASC 归属不同，感染方案需要分别处理，不能强行共享同一个 Character 类。

AShootCharacterBase 的 StartDeath 会：

- 进入 DeathStarted。
- 停止移动和关闭碰撞。
- 广播死亡委托。
- 取消全部 Ability。
- 移除 GameplayCue。

因此普通人类感染不能简单调用通用 Die 再尝试把尸体变成僵尸。感染转换必须有独立状态和独立转换时机。真正死亡、永久淘汰和观战才进入终结死亡链。

### 2.4 当前技能链

当前技能主线已经明确：

- Experience 载入时授予公共能力和当前性别能力。
- SkillLoadoutConfig 只提供本局可获得的技能目录，不会把整个目录入场即授予。
- PlayerState 上的 UShootSkillLoadoutComponent 固定四槽，服务器写入，OwnerOnly 复制。
- 获取技能、升级技能、随机抽取和未来商店购买最终都走 AcquireSkill 事务。
- 每个槽位独立持有 UShootAbilitySet 的撤销句柄。
- UShootAbilitySet::GiveToAbilitySystem 收到 InputTagOverride 时使用该槽位输入标签。
- 当前 SlotInputTags 和 SlotInputActions 顺序为 Q、E、C、X，实际键鼠、手柄和触摸映射仍由 Enhanced Input 与 CommonUI 配置。
- Definition 的 CooldownTag 与 GameplayEffect 的冷却标签一致，UI 直接查询同一个 ActiveGameplayEffect。
- InitializeRoundForAll 只重置属性，不重新授予 Match Skill，不改变技能规格数量和冷却。
- Experience 卸载时 ClearMatchSkills，然后回收性别和公共能力。
- SaveGame v3 只保存 Persistent 物品、资源、双主角外观和 QuickBar，不保存技能槽、技能等级和 AbilitySpec。

当前 `UShootSkillLoadoutComponent::RegrantSlot` 直接使用 `UShootSkillDefinition::AbilitySet`、技能等级和 Experience 的槽位 InputTag 重新授予能力。感染转换需要在不改变 `AcquireSkill` 事务的前提下增加角色绑定解析：同一 SkillDefinition 根据新 RoleTag 选择对应 AbilitySet，没有绑定时只撤销该槽位能力并保留槽位记录。`ClearMatchSkills` 仍只用于 Experience 卸载或离开 Match，不能用于感染转换。

PlayerState 源码中仍保留 Level、XP、AttributePoints、SpellPoints 字段和复制回调。当前 SaveGame v3 与技能状态文档已经把等级、属性和技能排除在账号存档之外，生化模式沿用这一结论，不把这些字段作为新的存档入口。它们属于后续遗留字段清理范围。

### 2.5 阵营识别

当前阵营判断由 UShootAbilitySystemLibrary::GetTeamAttitudeForActors 统一处理：

1. 直接读取 Actor、Pawn、PlayerState 或 Controller 上的 ILyraTeamAgentInterface。
2. 沿 Instigator 链解析武器、投射物或装备表现 Actor 的归属。
3. Team ID 无法解析时回退到 Faction_Player 和 Faction_Enemy。
4. 任一方无法解析时返回 Neutral。

当前默认玩家队伍为 1，敌人控制器默认队伍为 2。生化模式需要动态修改玩家的队伍和角色，并让 PlayerState、Pawn、Controller、ASC 阵营标签、AI Perception 和 UI 同步刷新。

Faction_Player 和 Faction_Enemy 是现阶段的二元粗粒度标签，无法完整表达 Human、Zombie、特殊角色和中立状态。队伍关系以 ILyraTeamAgentInterface 和 Team ID 为权威，Faction 标签只作为效果筛选和表现辅助。需要新增更明确的模式标签或扩展现有标签体系。

## 3. 目标架构

### 3.1 逻辑调用链

~~~text
Experience Definition
  -> 模式 GameMode 选择并启动规则
  -> GameState 保存并复制 Match、Round、人口和目标快照
  -> PlayerState 保存玩家的 Team、Role、感染状态、死亡状态和 Match Skill
  -> Pawn 表现当前形态、碰撞、移动和 Avatar
  -> ASC 执行角色能力、武器能力、技能、GameplayEffect 和 GameplayCue
  -> GameplayMessage、ViewModel、CommonUI 和 UIExtension 表现状态
~~~

~~~text
Experience
  -> Experience-specific Role AbilitySet
  -> Health Depleted Response Ability
  -> Zombie Attack Ability
  -> Damage / Control / Healing GE
  -> Role Transition Service
  -> Death / Respawn Ability
  -> Last Human / Objective / Victory
~~~

### 3.2 职责边界

| 层 | 负责内容 | 主要状态 |
| --- | --- | --- |
| Experience | 选择本局玩法组合、PawnData、Role AbilitySet、健康归零响应 Ability、技能目录、HUD 和输入 | 当前 Experience |
| GameMode | 服务器回合、感染、角色、死亡、重生、胜负、奖励和加入裁决 | 规则执行状态 |
| GameState | 向所有客户端公开 Match、Round、人口、时间、目标和最终阶段 | 复制快照 |
| PlayerState | 玩家跨 Pawn 的阵营、角色、感染、死亡、成长和 Match Skill | 玩家身份状态 |
| Player ASC | 角色能力、技能能力、属性、冷却、状态 GE 和 Cue | GAS 状态 |
| Pawn | 当前形态、移动、碰撞、动画、武器表现和 Avatar | 当前生命 |
| AIController | Perception、目标评分、Blackboard、BehaviorTree 和接敌槽位 | AI 决策状态 |
| 地图规则 Actor | 门、电梯、桥、检查点、补给、目标阶段和逃生区域 | 地图局部状态 |
| UI | 读取复制状态、ViewModel 和消息并表现，不裁决胜负 | 本地显示状态 |

### 3.3 推荐新增的逻辑对象

名称可在实现时调整，职责先固定：

- Infection Experience Definition：在现有 Experience 定义上组合生化 Role AbilitySet、响应 Ability、GameplayEffect、PawnData 和地图功能。
- Infection GameMode：继承现有 ShootGameModeBase，处理服务器生命周期和规则事务。
- Infection GameState Component：保存并复制 Match、Round、人口、时间、最终阶段和地图目标快照。
- Health Depleted Response Ability：由 Experience 选择健康归零后的死亡或感染能力。
- Role Transition Service：只执行已经由 GAS Ability 决定的角色转换事务。
- Infection Role Definition：声明 Human、Zombie、特殊角色的形态、属性、AbilitySet、响应 Ability 和死亡资格。
- Infection Player Runtime State：保存 PlayerState 上与本回合有关的动态字段。
- Infection Map Objective：由地图 Actor 实现门、桥、检查点、补给和目标阶段。

健康归零结果由当前 Experience 授予的 GAS Ability 决定，GameMode 只提供服务器权限和角色转换入口。服务器写入 GameMode 所有权，公开状态写入 GameState。不要让客户端通过 GameState 反向执行规则。

## 4. 数据定义

### 4.1 Experience 级定义

生化 Experience 至少需要声明：

- Match 是否多回合以及回合数量。
- RoundPreparation、RoundActive、RoundEnding 的时长。
- Initial Infection 的初始僵尸数量表或曲线。
- Human、Zombie、InitialZombie、SpecialHuman、SpecialZombie 和变体角色目录。
- Human、Zombie、特殊角色的 Role AbilitySet，以及健康归零后的 Death 或 Infection Response Ability。
- Zombie 普通伤害、直接清空生命值、感染攻击和防化服能力所使用的 GameplayEffect。
- Death Policy、Respawn Policy、Victory Policy 和 Join Policy。
- 最后一名人类和最终决战触发规则。
- PlayerData、ZombieData、AI 行为资产和各角色 AbilitySet。
- SkillLoadoutConfig、技能获取来源、技能升级和角色适用范围。
- 地图目标、逃亡阶段、补给箱和检查点规则。
- 奖励、局内经验、生化 Z、金币和商店配置。

Experience 只声明 AbilitySet、GameplayEffect、Role Definition、PawnData 和地图功能的组合关系。感染或死亡的差异由被授予的 Ability 对象承担。

### 4.2 角色定义

每个角色定义至少包含：

- TeamId 或 Team Tag。
- Role Tag。
- PawnData 或形态配置。
- 基础属性 GameplayEffect。
- 角色固有 AbilitySet。
- 主动攻击、感染、控制、恢复和被动能力。
- 生命、护盾、护甲、移动、击退、硬直和减速抗性。
- 角色可获得的感染攻击、归零响应、防护和转换 Ability。
- 死亡原因处理、永久淘汰条件和重生条件。
- 外观、动画、音效、UI 图标和提示文案。
- 进化阶段或变体资格。

角色定义是数据源。代码通过角色标签和配置读取行为，不在基类中堆叠 ZombieType、IsPlayer 或 IsHero 分支。

### 4.3 玩家运行时状态

工作结构 FInfectionPlayerRuntimeState：

- 参战资格：Active、Spectator、Waiting、Disconnected。
- Team：Human 或 Zombie。
- Role：普通、初始、特殊、英雄、Hunter、进化阶段等。
- Round 状态：Alive、Infected、PendingInfection、Respawning、PermanentDead。
- Infection 状态：当前角色、转换锁、感染来源和由 Ability 或 GameplayEffect 持有的防护状态。
- 死亡信息：死亡原因、终结类型、击杀来源、死亡时间和是否永久淘汰。
- 重生信息：是否允许重生、重生计时、重生点和重生次数。
- Match 进度：技能构筑、局内等级、经验、金币和生化 Z。
- 变体状态：只保留确实需要跨 Pawn 或跨能力访问的状态，临时技能状态归属对应 ASC。

PlayerState 是这份状态的长期归属。Pawn 被销毁或替换时，玩家身份和 Match Skill 不随 Pawn 丢失。

### 4.4 GameState 公开快照

工作结构 FInfectionMatchSnapshot：

- Match 阶段和当前 Round 索引。
- Round 阶段、开始时间、剩余时间和阶段结束原因。
- AliveHumanCount、ActiveZombieCount、PermanentDeadCount、SpectatorCount。
- 初始僵尸数量、当前母体或特殊角色信息。
- LastHuman 阈值、是否已触发和最终阶段状态。
- 地图目标阶段、逃亡安全区状态和决战状态。
- RoundWinner、MatchWinner、结算状态和奖励阶段。
- 加入规则、重生规则和当前 Experience、Role AbilitySet 标识。

所有计数都由服务器依据玩家运行时状态和有效 AI 人口计算。击杀提示、客户端 Actor 数量和本地轮询只做表现来源。

### 4.5 生化能力组合

生化模式不建立感染触发枚举或通用感染规则表。不同 Experience 通过 AbilitySet 选择能力：

- 基础感染 Experience 给 Human Role 授予健康归零感染 Ability，给 Zombie Role 授予普通伤害攻击 Ability。
- 直接感染 Experience 给 Zombie Role 授予使用清空生命值 GameplayEffect 或 Execution 的感染攻击 Ability。该效果绕过 IncomingDamage 的 Shield 吸收路径，直接让 Health 归零，默认不修改 Shield。
- 防化服由 Human Skill 或 Role Ability 授予一次性防护 Ability 和带有感染效果免疫的 GameplayEffect。免疫发生在伤害效果执行前，攻击不扣 Health，也不恢复 Health。
- 两次攻击的变体使用普通伤害攻击 Ability 与不同伤害 GameplayEffect、属性和护盾配置，让生命值经过两次命中后归零，不建立通用命中计数器。
- 特殊感染、延迟感染和解毒由独立 Ability 负责，能用 GAS 事件表达的部分使用 GameplayTag，不把分支塞进公共伤害代码。

健康归零只提供统一的 GAS 事件入口。最终由当前 Experience 是否授予死亡响应 Ability 或感染响应 Ability 决定结果。

### 4.6 死亡与重生定义

死亡和重生使用 Experience 选择的策略对象，不使用按 Experience 名称分支的 GameMode 代码。策略对象至少有三种多态实现：

- `UShootZombieDeathPolicy_PermanentDeath`：本回合永久淘汰并进入观战。
- `UShootZombieDeathPolicy_RespawnUnlessSpecialKilled`：普通击杀延迟重生，带有永久终结标签的击杀永久淘汰。
- `UShootZombieDeathPolicy_InfiniteRespawn`：允许持续重生，人口归零不直接触发人类胜利。
- 特殊僵尸的终结条件：爆头、近战、英雄终结、指定技能或地图目标。
- 普通人类伤害归零后的结果由当前 Human Role AbilitySet 选择感染响应、死亡响应或其他响应 Ability。
- 重生延迟、重生点、出生保护、属性重置和角色恢复。
- 退出、断线、自杀、环境死亡和 OutOfWorld 的计数及奖励。
- 当前 Round 结束后是否保留玩家身份和 Match Skill。

### 4.7 Skill Definition 扩展

现有 UShootSkillDefinition 需要增加生化模式可读配置：

- AllowedTeamTags。
- AllowedRoleTags。
- 同一逻辑技能在不同 RoleTag 下对应的 AbilitySet 或能力定义。没有对应绑定时，该槽位只保留记录并暂停授予能力。
- 角色绑定使用 GameplayTag 到 AbilitySet 的数据映射，不增加 Human 或 Zombie 枚举。现有 `AbilitySet` 作为非角色变体的默认绑定，生化技能需要为可用 Role 显式配置角色绑定。
- 共享能力、角色变体和角色专属能力的显示与行为定义。
- 每个等级的角色能力和数值变化。
- 感染能力、抵抗、解毒、救援、逃亡和终结条件的标签。
- 技能是否跨 Round 保留。
- 技能获得来源和当前变体的可用条件。

技能变更必须继续使用 SkillLoadoutComponent 的统一事务和 GrantedHandles。感染转换时保留槽位、SkillId、等级、获得记录和逻辑冷却，先回收旧 Role 绑定的能力句柄，再根据新 RoleTag 授予对应绑定。技能条目不能自行从 GA 直接修改四槽。

### 4.8 数据驱动约束

- 初始僵尸数量、角色目录、技能池、回合配置和变体模块放在 DataAsset 或 EditDefaultsOnly 配置中。
- C++ 构造函数只创建组件和设定通用默认值，不加载 Game 资产，不逐条填充目录。
- 多个 Experience 需要共享敌人目录和难度倍率时，再建立统一 Definition 并一次性迁移，避免蓝图和表格双写。
- 地图局部事件由地图 Actor 配置，GameMode 只读取目标结果和阶段变化。

## 5. Match 与 Round 生命周期

### 5.1 Match 生命周期

1. GameMode 解析并选择生化 Experience。
2. Experience Manager 加载定义，授予公共和性别能力。
3. GameState 建立生化公开状态。
4. GameMode 收集参战玩家和加入策略。
5. 创建或重置 Match 级技能、奖励和变体状态。
6. 进入第一个 Round。
7. 每个 Round 结束后按规则清理回合状态，继续下一回合。
8. Match 结束后结算奖励，卸载 Experience。
9. Experience Manager 先清理四槽 Match Skill，再回收其他 Experience AbilitySet。
10. RuntimeOnly 武器和副本临时数据回到统一清理路径，不进入账号存档。

### 5.2 Round 状态表

| 状态 | 进入条件 | 服务器动作 | 退出条件 |
| --- | --- | --- | --- |
| RoundWaiting | Match 可开始或上一回合清理完成 | 收集参与者、检查加入和准备状态 | 达到开始条件 |
| RoundPreparation | 回合建立 | 全部合格参与者设为 Human，初始化角色、属性、武器和地图阶段 | 准备计时结束 |
| InitialInfection | 准备结束 | 计算初始数量、随机选择感染者、授予初始角色能力 | 感染事务完成 |
| RoundActive | 初始感染完成 | 处理伤害、感染、死亡、重生、目标、成长和最终阶段 | 胜负条件成立或计时结束 |
| RoundEnding | 回合结果确定 | 锁定战斗，广播结果，结算并清理 Round 状态 | 下一回合或 Match 结束 |

所有状态切换需要幂等。重复的 OnRep、死亡回调、断线回调、重生计时器和地图目标回调不能重复改变人口、奖励或胜负。

### 5.3 回合初始化

回合初始化顺序：

1. 清理上一回合的感染、待感染、死亡、重生、士气、进化和地图目标状态。
2. 将有资格参战的玩家设为 Human 和默认 Round Role。
3. 为当前 Pawn 或新 Pawn 初始化默认属性。
4. 恢复当前角色的 RuntimeOnly 武器和 QuickBar 引用。
5. 清理角色固有 AbilitySet 的旧句柄，再按当前 Role 授予角色能力。
6. 保留 Match Skill 槽位、等级和冷却，除非 Experience 明确配置 Round 重置。
7. 建立出生点、目标阶段和计时器。
8. 更新 GameState 快照并广播 Round 状态。

当前 InitializeRoundForAll 已经采用属性重置、不重授 Match Skill 的边界。生化模式新增角色切换时，角色 AbilitySet 必须单独管理句柄，不得把所有能力放入回合重置。

## 6. 初始感染与动态阵营

### 6.1 初始感染选择

服务器在 RoundPreparation 结束后：

1. 生成有效参战玩家列表，排除观战、断线、永久淘汰和不允许当前 Round 参加的玩家。
2. 把合格玩家统一设为 Human，清除旧回合感染状态。
3. 根据总玩家数、最小值、最大值和配置表计算初始僵尸数量。
4. 使用服务器随机源从合格 Human 中抽取不重复目标。
5. 按顺序分配 InitialZombie、Mother、SpecialZombie 等角色。
6. 为角色授予属性、AbilitySet、感染能力和表现状态。
7. 原子更新人数、时间和 Round 状态。
8. 广播初始感染事件和 UI 快照。

初始感染数量不能写死为一人。玩家数量不足、可选目标数量不足、机器人补位、迟到玩家和 Listen Server Host 都要走同一套候选列表规则。

### 6.2 阵营转换

玩家感染成功时：

- PlayerState 写入新的 TeamId 和 RoleTag。
- PlayerState 的 Team Changed 委托广播。
- 当前 Pawn、Controller、ASC 阵营标签和 AI Perception 刷新。
- 移除旧角色能力，授予新角色能力。
- 由 Zombie Role Definition 处理角色表现和形态：同 Pawn 时切换 CO 使用的网格与动画实例，替换 Pawn 时生成 Zombie Pawn 并重新绑定 Avatar。具体 Zombie Pawn、CO 和资产仍由后续配置决定。
- 按 SkillDefinition 的角色绑定处理 Match Skill，保留槽位、SkillId、等级、获得记录和逻辑冷却；共享能力继续使用，存在 Zombie 绑定的技能切换绑定，没有绑定的 HumanOnly 技能暂停授予但不删除槽位记录。
- 按转换策略处理武器、装备和属性。
- 重新计算人口并触发 LastHuman、FinalPhase 和胜负检查。
- 向感染者、攻击者、队友和全体玩家发送对应消息。

AI Controller 没有 PlayerState，队伍需要写入其 CachedTeamID。玩家使用 PlayerState 的 TeamId，AI 使用 Controller 的 TeamId，所有攻击和目标判断继续通过 Team Attitude。

## 7. 感染事务

### 7.1 调用关系

感染不通过通用请求对象和枚举求值。攻击 Ability 负责应用自己的 GameplayEffect，健康归零后由当前 Experience 已授予的响应 Ability 处理结果。

~~~text
Zombie Attack Ability
  -> Attack GameplayEffect
  -> Health reaches zero
  -> Event.Health.Depleted
  -> Experience-selected Response Ability
  -> Death Ability or Infection Ability
  -> Role Transition Service
  -> Recompute Counts
  -> Broadcast Messages
~~~

普通感染攻击进入 IncomingDamage 的 Shield 到 Health 路径，Health 归零后触发响应 Ability。直接感染使用独立 Impact GameplayEffect 或 Execution，直接作用于 Health，穿透 Shield 且默认不修改 Shield，然后通过同一个 Event.Health.Depleted 入口触发响应 Ability。普通 PVE Experience 不授予感染响应 Ability，所以人类血量归零仍进入死亡。

### 7.2 请求数据

感染相关上下文沿用 GAS 的 GameplayEffectSpec、FGameplayEffectContextHandle、SourceTags、TargetTags 和命中信息：

- Source Actor、Target Actor、Instigator、EffectCauser 和对应 ASC。
- Damage Tag、Attack Tag、Hit Bone、WeakSpot、Melee、Grenade 和 Environment 等命中元数据。
- 命中位置、方向、距离、视线和服务器时序。
- 目标当前 Health、Shield、Armor、RoleTag 和 ActiveGameplayEffect。
- 攻击 Ability 的 SpecHandle 或当前 Ability 实例，供伤害归属和能力效果使用。

### 7.3 目标与能力合法性

目标是否具备感染资格只由攻击 Ability、GameplayEffect 和健康归零响应 Ability 各自处理，不落成独立模式策略表或感染枚举：

1. Zombie Attack Ability 在命中帧通过现有目标验证、Team Attitude、距离、视线、朝向和死亡状态检查。
2. 生化攻击 Impact GameplayEffect 统一带有语义标签 `Damage.Infection`，普通 PVE 伤害不带该标签。GameplayEffect 的 Application Tag Requirements、Target Tags 和免疫效果决定该效果能否作用于目标。
3. Health Depleted Response Ability 只响应自己所属 Role 的健康归零事件。
4. Role Transition Service 检查当前 Round、Team、Role、DeathState 和转换锁。
5. 防化服的免疫 GameplayEffect 以 `Damage.Infection` 为应用免疫条件，在 Impact GameplayEffect 执行前阻止普通感染和直接感染。有效命中后的感染尝试事件由防化服 Ability 消耗一次资格。
6. 特殊角色、普通护盾和解毒技能通过自己的 Ability 或 GameplayEffect 改变上述结果。

### 7.4 感染结果

不建立全局感染结果枚举。结果由能力是否成功完成、GameplayEffect 是否成功施加、PlayerState 的 Team 和 Role、DeathState 以及对应 GameplayMessage 表达：

- 普通 PVE：Health reaches zero，Death Response Ability 调用 Die。
- 基础感染：Health reaches zero，Infection Response Ability 调用 Role Transition Service。
- 防化服：感染 Impact GameplayEffect 被防护效果拦截，伤害不会执行，Health 不发生变化，也不做 Health 恢复；防护 Ability 消耗自身的一次使用资格，健康归零响应不发生感染转换。
- 直接感染：感染攻击 Ability 应用直接作用于 Health 的 GameplayEffect 或 Execution，穿透 Shield 并让 Health 归零，目标仍由 Infection Response Ability 转换。
- 待感染、解毒、特殊终结：分别由独立 Ability 和 GameplayEffect 持有自己的状态，不扩展公共感染枚举。

### 7.5 成功提交顺序

感染响应 Ability 调用 Role Transition Service 后，服务器一次事务完成：

1. 设置事务锁或 Pending 状态，阻止重入。
2. 保存旧 Role、Team、Pawn、Role AbilitySet 句柄、Match Skill 槽位记录、GrantedHandles 和逻辑冷却状态。
3. 清理旧角色 GameplayCue、临时 GE、移动锁、攻击目标和表现状态，不清理 Match Skill 自己持有的槽位记录和逻辑冷却。
4. 从旧角色 AbilitySet 句柄移除能力。
5. 更新 PlayerState TeamId、RoleTag 和当前回合角色状态。
6. 按 Role Definition 选择替换 Pawn、PawnData 或同 Pawn 的角色表现切换。
7. 同 Pawn 时切换 CO 网格与动画实例，替换 Pawn 时重新绑定 PlayerState ASC 的 Owner 和新 Pawn Avatar。
8. 按新 RoleTag 解析每个 Match Skill 的角色绑定，回收旧绑定能力句柄，授予共享或 Zombie 绑定；无绑定的槽位进入暂停状态。
9. 授予新角色 AbilitySet，并保存独立句柄。
10. 刷新 Controller、AI Perception、ASC 标签和本地 UI。
11. 更新人数、LastHuman、FinalPhase、Objective 和胜负。
12. 广播 RoleChanged、TeamChanged、SkillLoadoutChanged 和 CountChanged。
13. 清除事务锁，保证下一次合法请求可处理。

任何一步失败都必须保留旧状态或执行完整回滚，不能出现 Team 已变更但 Pawn、ASC 能力和人数仍是旧状态的半转换。

### 7.6 伤害与感染的关系

- 普通伤害通过 IncomingDamage、Shield、Health 和属性规则结算。
- Health reaches zero 只产生统一的 Event.Health.Depleted，具体响应由 Experience 授予的 Ability 决定。
- 感染成功后不追加一次普通死亡奖励，感染响应 Ability 直接进入角色转换事务。
- 攻击来源、命中部位和伤害类型必须保留，用于击杀归属、永久终结和 UI 反馈。

## 8. 死亡、重生与胜负

### 8.1 死亡原因

建议统一记录：

- PlayerKilled
- Infected
- Environment
- Suicide
- OutOfWorld
- Disconnect
- SpecialExecution
- ObjectiveFailure

死亡原因和终结类型分开。Infected 表示身份转换，PermanentDead 表示当前参与资格永久结束，DeathStarted 表示 Pawn 进入终结表现。

### 8.2 普通僵尸死亡

普通 Zombie 的死亡和重生不是未定义需求，而是由 Experience 选择的既有策略。策略使用多态对象承载，不在 GameMode 中按模式名称分支：

```cpp
UCLASS(Abstract)
class UShootZombieDeathPolicy : public UPrimaryDataAsset
{
    GENERATED_BODY()

public:
    virtual void ResolveDeath(
        AShootCharacterBase& Zombie,
        const FShootDeathContext& DeathContext,
        UShootZombieLifecycleService& Lifecycle) const PURE_VIRTUAL(
            UShootZombieDeathPolicy::ResolveDeath, );
};

UCLASS()
class UShootZombieDeathPolicy_PermanentDeath
    : public UShootZombieDeathPolicy
{
    GENERATED_BODY()
};

UCLASS()
class UShootZombieDeathPolicy_RespawnUnlessSpecialKilled
    : public UShootZombieDeathPolicy
{
    GENERATED_BODY()
};

UCLASS()
class UShootZombieDeathPolicy_InfiniteRespawn
    : public UShootZombieDeathPolicy
{
    GENERATED_BODY()
};
```

三种策略的行为固定为：

- `PermanentDeath`：死亡后本回合永久淘汰并进入观战。
- `RespawnUnlessSpecialKilled`：普通击杀按配置延迟重生，死亡上下文带有爆头、近战终结、英雄终结或指定技能等永久终结标签时永久淘汰。
- `InfiniteRespawn`：始终允许重生，人口归零不直接触发人类胜利，胜负交给时间、逃亡或目标模块。

Experience 只引用策略对象并提供参数资产。死亡上下文携带终结标签，策略对象调用生命周期服务完成观战、重生、出生点和人口更新。策略类型已经由核心玩法确定，具体 Experience 的选择、重生参数、出生保护和永久终结标签仍需配置。

重生事务：

1. 标记 DeathStarted 和 DeathFinished。
2. 依据死亡原因和终结类型决定永久淘汰或可重生。
3. 可重生时创建唯一重生计时器。
4. 计时结束后选择有效出生点并生成对应角色 Pawn。
5. 绑定 AIController 或 PlayerController。
6. 初始化属性、角色 AbilitySet、碰撞和出生保护。
7. 更新 GameState 人口和 UI。

计时器、死亡委托和 Pawn EndPlay 必须使用同一重生事务 ID，防止同一角色重生两次。

### 8.3 玩家死亡约束

当前通用 AShootGameModeBase 通过 bRespawnPlayers 和 PlayerRespawnDelay 控制普通玩家重生。生化模式需要覆盖该入口：

- 感染成功不调用通用 PlayerDied。
- 普通人类真正死亡时按角色和模式决定感染、观战或重生。
- Zombie 玩家死亡时按 Zombie Death Policy 决定重生或永久淘汰。
- 重生时保留 PlayerState ASC 和 Match Skill，重新绑定新 Pawn Avatar。
- 新 Pawn 只恢复当前生命、护盾、移动和装备状态，不从 SaveGame 重新加载技能。

### 8.4 最后一名人类

每次人数变更后按阈值检测。首次跨过阈值时只触发一次：

- 写入 GameState FinalPhase 或 LastHuman 状态。
- 应用人类临时增益或英雄规则。
- 开放地图出口、补给箱或特殊武器。
- 调整僵尸重生、攻击和目标规则。
- 广播全体玩家的阶段提示。

LastHuman 事件不能与 ZombieVictory 检查合并。事件触发后还要允许地图、决战、逃亡和特殊角色规则继续运行。

### 8.5 胜负计算

ZombieVictory 条件：

- AliveHumanCount 为零，且当前规则没有无限重生或替代目标。
- 逃亡时间结束且人类未满足安全区规则。
- 人类保护的阻塞目标失败。

HumanVictory 条件：

- RoundActive 计时结束时仍有有效人类。
- 所有需要永久淘汰的 Zombie 已失去继续参战资格。
- 逃亡、护送或地图目标完成。

最终决战由玩家数、剩余时间、特殊角色、目标阶段和配置条件组合触发，不能只写成 LastHuman 的单一硬编码分支。

## 9. GAS 与技能化实现重点

### 9.1 生化模式的能力分层

生化模式的技能化分三层：

1. Common AbilitySet：移动、交互、相机、通用武器和 Experience 公共能力。
2. Role AbilitySet：Human、Zombie、InitialZombie、Mother、Hero、Hunter 和特殊角色固有能力。
3. Match Skill AbilitySet：玩家在当前 Match 获取、升级和配置的四槽技能。

生化差异优先放在 Role AbilitySet 和 Match Skill AbilitySet。Health、Shield、Damage、Death 和 Infection 都通过 GAS 能力与 GameplayEffect 组合，不在公共类里识别 Experience 名称。

### 9.2 PVE 与生化感染的 AbilitySet 隔离

| Experience | Human 归零响应 | Zombie 攻击能力 | 生命值归零结果 |
| --- | --- | --- | --- |
| CF 或 CSOL 大灾变 PVE | Death On Health Depleted Ability | Zombie Melee Damage Ability | 调用现有死亡链，人类不会感染 |
| 基础生化感染 | Infection On Health Depleted Ability | Zombie Melee Damage Ability | 进入 Role Transition，继续以 Zombie 参战 |
| 直接感染变体 | Infection On Health Depleted Ability | Zombie Infection Melee Ability 或不同 Impact GE | 直接 Impact GE 或 Execution 穿透 Shield 将 Health 清零，再由感染响应转换 |
| 防化服变体 | 独立的 Hazmat Infection Resistance Ability 和免疫 GE | 当前 Experience 的 Zombie 攻击能力 | 感染 Impact GE 在执行前被拦截，防护消耗一次，Health 不变 |

当前 AEnemyBotController、AEnemyBotCharacter 和 UShootGA_ZombieMelee 属于 PVE 打僵尸链，职责是让 Zombie 对 Human 造成普通伤害并处理 Zombie 自身死亡。它们不是生化感染模式代码。生化模式可以复用目标验证、攻击动画和命中窗口，但通过不同 Role AbilitySet 授予感染攻击或感染响应能力。

### 9.3 Health 归零的 GAS 响应入口

当前 UShootAttributeSet::HandleIncomingDamage 已完成 Shield 到 Health 的权威结算，但在 FinalHealth 小于等于零时直接调用 ICombatInterface::Die，并通知通用 GameMode。这会把所有玩法固定成死亡，必须在实现生化模式前拆开。

公共伤害代码只负责发送健康归零事件，不负责选择死亡还是感染：

~~~cpp
if (FinalHealth <= 0.0f && Context.TargetASC)
{
    FGameplayEventData EventData;
    EventData.Instigator = Context.SourceActor.Get();
    EventData.Target = Context.TargetActor.Get();
    EventData.ContextHandle = /* 由当前伤害 GE 传入的上下文 */;

    Context.TargetASC->HandleGameplayEvent(
        Event.Health.Depleted,
        &EventData);
}
~~~

健康归零事件必须覆盖两条 GAS 路径：

- 普通伤害先写入 IncomingDamage，由现有 Shield 到 Health 结算完成后检查 Health 从正数到零的变化。
- 直接感染的专用 GameplayEffect Execution 直接对 Health 产生负向 Modifier，不写入 IncomingDamage，因此不经过 Shield 吸收。该路径在 GameplayEffect 完成后调用同一个健康归零事件出口。

直接感染的 Execution 读取目标当前 Health 或 MaxHealth，计算足以归零的负向值，不写死伤害数值，不调用 AttributeSet 的 `SetHealth`，也不清理 Shield。所有健康归零路径只能由 Experience 授予的响应 Ability 决定后续是死亡还是感染。

Experience 必须给每个可受伤角色授予一个健康归零响应 Ability：

~~~cpp
UCLASS(Abstract)
class UShootGA_HealthDepletedResponse : public UShootGameplayAbility
{
    GENERATED_BODY()

protected:
    virtual void RespondToHealthDepleted(
        const FGameplayEventData& EventData) PURE_VIRTUAL(
            UShootGA_HealthDepletedResponse::RespondToHealthDepleted, );
};

UCLASS()
class UShootGA_DeathOnHealthDepleted
    : public UShootGA_HealthDepletedResponse
{
    GENERATED_BODY()

protected:
    virtual void RespondToHealthDepleted(
        const FGameplayEventData& EventData) override;
};

UCLASS()
class UShootGA_InfectionOnHealthDepleted
    : public UShootGA_HealthDepletedResponse
{
    GENERATED_BODY()

protected:
    virtual void RespondToHealthDepleted(
        const FGameplayEventData& EventData) override;
};
~~~

DeathOnHealthDepleted 调用现有 Die 和死亡统计。InfectionOnHealthDepleted 调用 Role Transition Service，不调用 Die、StartDeath 或通用 PlayerDied。两者由 Experience AbilitySet 互斥选择，不在 UShootAttributeSet 写模式判断。

在移除 AttributeSet 当前的直接 Die 调用前，必须先把 DeathOnHealthDepleted 配入现有 PVE Experience 和 Zombie AbilitySet，确保 PVE 行为不发生回归。

### 9.4 Zombie 攻击的面向对象结构

当前 Zombie 近战的公共流程是目标复核、攻击动画、命中 Notify、一次命中保护、攻击 GE 和冷却。普通伤害和感染伤害的差异只放在 Impact Effect 的多态实现或 AbilitySet 选择中。

~~~cpp
UCLASS(Abstract)
class UShootGA_ZombieMeleeBase : public UShootGameplayAbility
{
    GENERATED_BODY()

protected:
    virtual void ExecuteMeleeImpact(AActor* TargetActor) PURE_VIRTUAL(
        UShootGA_ZombieMeleeBase::ExecuteMeleeImpact, );

    void ValidateTargetAtImpact(AActor* TargetActor) const;
    void PlayAttackMontage();
};

UCLASS()
class UShootGA_ZombieMeleeDamage : public UShootGA_ZombieMeleeBase
{
    GENERATED_BODY()

protected:
    virtual void ExecuteMeleeImpact(AActor* TargetActor) override;
};

UCLASS()
class UShootGA_ZombieMeleeInfection : public UShootGA_ZombieMeleeBase
{
    GENERATED_BODY()

protected:
    virtual void ExecuteMeleeImpact(AActor* TargetActor) override;
};
~~~

UShootGA_ZombieMeleeDamage 使用现有 AttackEffectClass 和 AttackStatusEffectClass。UShootGA_ZombieMeleeInfection 使用感染 Experience 选择的普通伤害 GE 或直接作用于 Health 的 GE/Execution。若两者只有 GE 引用不同，可以复用同一个 GA CDO，通过不同 AbilitySet 资产配置，不新增子类；只有命中语义不同才新增 C++ 子类。

AI Controller 和 BehaviorTree 只按 Zombie 近战 Ability Tag 请求能力。PVE 还是感染由 Experience 选择授予哪一个 AbilitySpec，AI 不读取 Experience 名称。

当前 UShootGA_ZombieMelee 的命中时序必须保持：

- HandleMeleeNotify 只保留一个 bHitApplied 写入点。
- 命中 Notify 只能作为命中窗口信号。
- 服务器重新验证距离、视线、Team Attitude、死亡状态和目标。
- 一次攻击只应用一次直接伤害，攻击状态 GE 是否附带由能力资产决定。
- PlayerState ASC 和 Enemy Character ASC 的能力归属继续分开。

### 9.5 四种玩法只改能力组合

基础感染：

- Human Role AbilitySet 授予 InfectionOnHealthDepleted。
- Zombie Role AbilitySet 授予普通伤害攻击。
- Zombie 普通攻击通过现有 IncomingDamage 链将 Human Health 扣到零。
- Event.Health.Depleted 激活感染响应，PlayerState 转入 Zombie Team 和 Zombie Role。

直接感染：

- Zombie Role AbilitySet 改授予 ZombieMeleeInfection，或将同一近战 GA 的 Impact GameplayEffect 配为清空生命值。
- 直接 Impact GameplayEffect 或 Execution 直接对 Health 产生足以归零的负向 Modifier，穿透 Shield，默认不修改 Shield。
- 该效果不写入 IncomingDamage，但在效果完成后通过公共健康归零事件出口激活感染响应。
- 清空生命值仍然使用 GAS，不直接调用 AttributeSet 的 SetHealth。
- Human 响应能力不需要知道攻击是普通还是直接清空。

防化服抵消一次：

- Human 的技能或 Role AbilitySet 授予 HazmatInfectionResistance 和一次性免疫 GameplayEffect。
- 免疫 GameplayEffect 以 `Damage.Infection` 为应用免疫条件，在普通感染和直接感染 Impact GameplayEffect 执行前拦截攻击。
- 有效攻击命中后由 Zombie Attack Ability 发送感染尝试事件，防护 Ability 消耗一次使用资格。
- 被拦截的攻击不产生 IncomingDamage、Health 归零事件或 Health 恢复。
- InfectionOnHealthDepleted 继续负责没有防护时的转换。
- 现有 Status.ImmuneDeath 和 UShootEffect_ImmuneDeath 只能作为技术参考。它当前是持续时间型免死效果，不等于一次性防化服，不能直接改名复用。

两次普通攻击：

- Zombie 仍然使用普通伤害攻击 Ability。
- 由该 Experience 的 Human 属性、护盾和 Zombie 攻击 GE 数值让两次有效命中后 Health 归零。
- 不增加通用感染命中计数器。
- 如果未来需要与生命值无关的严格命中次数，再由独立的 Zombie Ability 或 Human Role Ability 负责，不污染基础感染链。

### 9.6 角色转换与技能状态

InfectionOnHealthDepleted 只负责调用角色转换服务，服务不负责判断攻击类型：

~~~cpp
UCLASS()
class UShootRoleTransitionService : public UObject
{
    GENERATED_BODY()

public:
    bool ConvertHumanToZombie(
        AShootPlayerState& PlayerState,
        const UShootRoleDefinition& ZombieRole,
        const FGameplayEventData& SourceEvent);
};
~~~

转换顺序：

1. 锁定 PlayerState，确认服务器、当前 Round、当前 Role 和 DeathState。
2. 保存旧 Role AbilitySet 句柄、当前 Pawn、四槽 Match Skill 记录、GrantedHandles 和逻辑冷却状态。
3. 回收 Human Role AbilitySet，保留 Common AbilitySet。
4. 更新 PlayerState 的 TeamId、RoleTag 和感染来源。
5. 按 Zombie Role Definition 选择替换 Pawn、PawnData 或同 Pawn 的形态转换。
6. 同 Pawn 时切换 CO 网格和动画实例，替换 Pawn 时重新绑定 PlayerState ASC 的 Owner 和新 Pawn Avatar。
7. 授予 Zombie Role AbilitySet，并保存独立句柄。
8. 让 SkillLoadoutComponent 按每个 SkillDefinition 的 Role Binding 处理四槽能力，槽位数据、等级、获得记录和逻辑冷却仍归 PlayerState。
9. 刷新 Controller、AI Perception、GameplayCue、UI 消息和 GameState 人口。
10. 最后检查 LastHuman、FinalPhase 和胜负。

Match Skill 角色绑定由 SkillDefinition 的 RoleTag 映射提供，不在转换服务中写 Human 或 Zombie 分支：

- 新 RoleTag 有绑定时，回收旧 Role 的 AbilitySpec 和 GrantedHandles，以原槽位、等级和输入标签授予新绑定。
- 新绑定使用同一个逻辑 CooldownTag 时保留冷却剩余时间，转换不能通过换能力免费刷新技能。
- 新 RoleTag 没有绑定时，只移除该槽位当前 Role 的能力，保留 SkillId、等级和获得记录，标记槽位暂停并通知 UI。
- 人类专属持续效果、动作锁、武器依赖和外观依赖随旧角色能力清理；通用效果只有在新 Role 有明确绑定时才保留。
- Role AbilitySet 与 Match Skill AbilitySet 使用独立句柄，感染只重建对应句柄，不把所有技能授予后再用运行时条件过滤。

角色转换服务是执行事务的对象，不是感染规则解释器。Pawn、CO、技能和能力都从 Role Definition 或 AbilitySet 读取，不在服务里写角色类型大分支。

### 9.7 Pawn、CO 与外观边界

生化模式不使用 Unity 式隐藏人类网格来伪造 Zombie，也不把隐藏组件作为角色状态。

- Gameplay Role、Team 和能力状态归 PlayerState、ASC 和 Role Definition。
- 当前人类角色继续使用项目已有 CO 外观链。
- Zombie Pawn 和 Zombie CO 尚未确定，作为 PawnData 或 Zombie Role Definition 的资产决策，不提前写死，也不影响 Team、Role、ASC 和 Match Skill 转换协议。
- 如果 Zombie 使用独立 Pawn 或独立 CO，感染时替换 Pawn 并重绑 PlayerState ASC。
- 如果后续证明人类和 Zombie 能共用 Pawn、骨骼和碰撞，感染时在同一个 Pawn 内切换 CO 网格和动画实例，再刷新碰撞、移动和表现参数。
- 不在感染逻辑中调用 SetVisibility、隐藏人类部件或强行修改 Mutable CO。

CO 是表现装配，不是感染机制。无论最终 Zombie 是否使用 CO，Team、Role、AbilitySet 和生命归零响应都不依赖外观实现。

### 9.8 实现顺序与验收

1. 新增 Event.Health.Depleted，并把公共伤害链从直接 Die 改为发送事件。
2. 为现有 PVE Experience 配置 DeathOnHealthDepleted，验证人类和 Zombie 仍然只死亡、不感染。
3. 新增 InfectionOnHealthDepleted 和 Role Transition Service，验证基础健康归零感染。
4. 把 Zombie 普通伤害 Ability 与感染 AbilitySet 分开，验证两种 Experience 不串规则。
5. 新增直接作用于 Health 的 Infection Impact GameplayEffect 或 Execution，验证直接感染穿透 Shield 且不依赖当前 Health 数值。
6. 以独立 Hazmat Ability 和应用免疫 GameplayEffect 实现防化服一次抵消，验证伤害不执行且不恢复 Health。
7. 通过普通伤害 GE 和属性配置验证两次命中归零，不增加公共命中计数器。
8. 为各 Experience 选择既有 Zombie Death Policy，验证普通死亡、特殊终结和无限重生。
9. 最后接入 Zombie PawnData 或 CO 方案，验证同 Pawn 的 CO 网格与动画实例切换或换 Pawn 路径不使用隐藏网格。

验收必须同时覆盖：

- PVE Experience 中 Human Health 归零进入 DeathOnHealthDepleted，Team 和 Role 不改变。
- 基础感染 Experience 中 Human Health 归零进入 InfectionOnHealthDepleted，PlayerState 继续参战并换成 Zombie Role。
- 直接感染 Ability 对不同 MaxHealth 的 Human 使用同一 GE 或 Execution 直接作用于 Health，穿透 Shield 仍能清空并转换。
- 防化服第一次在 Impact GameplayEffect 执行前阻止转换，消耗一次资格，Health 不变且不恢复，下一次有效攻击按感染规则处理。
- 两次普通命中通过伤害结算归零并感染，不存在感染命中计数器。
- 玩家 Zombie 使用 PlayerState ASC，AI Zombie 使用 Enemy Character ASC，两个 ASC 的 Role AbilitySet 句柄都能独立回收。
- 人类感染后 TeamId、RoleTag、CO 网格、动画实例、Role AbilitySet 和 Match Skill 角色绑定同步完成；四槽记录、等级和逻辑冷却保留，无 Zombie 绑定的技能只暂停。
- 三种 Zombie Death Policy 都能被 Experience 选择，普通击杀、特殊终结、永久淘汰和无限重生由对应策略处理。
- 人类和 Zombie 外观变化不依赖隐藏网格，不要求运行时修改 Mutable CO。
- 新增模式只改变 Experience、AbilitySet、Ability、GameplayEffect、GameplayTag 或 PawnData 配置，不在公共伤害链新增 Experience 分支。


## 10. 伤害、武器与控制

### 10.1 伤害入口

所有玩家、Zombie 和 AI 伤害继续进入 GAS：

~~~text
Weapon / Skill / Melee Notify
  -> Build GameplayEffect Spec
  -> SetByCaller Damage and Hit Metadata
  -> Target ASC IncomingDamage
  -> Shield / Armor / Health
  -> Damage, Infection or Death Rule
~~~

Team Attitude 过滤必须在攻击生成和目标最终结算两端都执行。友方、Neutral、死亡和无 ASC 对象不进入有效伤害或感染。

### 10.2 命中上下文

生化模式需要保留：

- Source、Target、Instigator、Ability 和 Weapon。
- HeadShot、WeakSpot、Melee、Grenade、Bullet、Bomb、Fall、Environment 和 Infection。
- 命中骨骼、命中位置、攻击方向和距离。
- 是否为特殊终结、英雄终结或近战终结。
- 是否触发感染、抵抗、待感染和解毒。

命中元数据可用 GameplayTag、SetByCaller 和结构化消息组合表达。Permanent Kill 不能依赖 UI KillMark 或伤害文本推断。

### 10.3 护甲、护盾与感染抵抗

Unity Health 的参考行为包括 MaxArmor、MaxHealth、CriticalHealthRatio、CurrentArmor、CurrentHealth、damageSources、Heal、Invincible 和 ResetHealth。它的护甲公式是先扣完整伤害到护甲，再把穿透部分扣到生命，适合作为原型边界参考。

Unreal 使用现有 AttributeSet、IncomingDamage、Shield、DamageReduction 和 GameplayEffect。感染抵抗应作为独立的 Human Skill、Role Ability 或状态 GameplayEffect，不把“护甲剩余大于零”直接等同于免疫。

### 10.4 击退、硬直、减速和恢复

- 击退通过服务器权威移动或 GameplayEffect 传递，目标角色的抗性由属性或标签决定。
- 硬直、减速和输入阻断使用状态 Tag 和 Ability Block，而不是在 C++ 中散布布尔开关。
- Zombie 脱离战斗恢复生命可使用角色专属周期 GE，受击、目标锁定和控制状态应阻断或打断恢复。
- 医疗、护盾、解毒和救援技能继续走现有 GAS 治疗和消息链。

### 10.5 近战

当前 Zombie PVE 近战链已经具备一部分运行实现，但整体仍是半成品：

- AIController 只请求 Zombie 近战 GA。
- GA 播放 Montage。
- AnimNotify 进入命中窗口。
- 服务器在 Notify 帧复核目标、Team Attitude、距离、朝向、视线和死亡状态。
- 通过攻击 GE 和状态 GE 结算伤害。
- Cooldown 由 GameplayEffect 负责，BehaviorTree Wait 只负责决策重试。

生化模式只复用命中窗口、目标复核和 GAS 伤害基础能力。感染 Experience 通过 Role AbilitySet 授予对应 Zombie Ability，不把感染逻辑塞进这条 PVE 链。

## 11. Zombie AI 与尸群

### 11.1 当前 Unreal PVE 链

当前 AEnemyBotController 已提供：

- Sight 和 Damage Perception。
- Hostile 目标筛选。
- 2 秒目标记忆。
- 目标切换 250cm 距离优势。
- TargetActor、TargetApproachLocation、HomeLocation 和 PatrolLocation 黑板键。
- 每个目标默认 4 个近战接敌槽位。
- 槽位满时在攻击范围外排队。
- 死亡时清理 Blackboard、Focus、Brain、目标记忆和接敌槽位。
- 近战 GA 激活与服务器目标复核。

AEnemyBotCharacter 已提供：

- Zombie Character ASC。
- Zombie AbilitySet 和句柄回收。
- AggroRange、AttackRange、AttackInterval、AttackDamage、RoamRadius 和 FacingDot 等 archetype 配置。
- Attack Effect、Status Effect、Montage 和 Zombie AnimNotify 链。
- 正式 AnimBP、死亡状态和服务器权威近战表现。

生化模式不直接复用这条 PVE 玩法语义。它只复用目标感知、接敌槽位、动画命中窗口和 GAS 基础能力，感染角色使用独立 AbilitySet、GA、GE 和必要的 BehaviorTree 子树。

### 11.2 目标选择

第一阶段沿用 Team Attitude、距离、感知和目标记忆。尸群规模扩大后增加目标评分：

- 目标距离和可见性。
- 最近伤害来源。
- 对 Owner 或队友的威胁。
- 目标当前 Human Role 和特殊角色价值。
- 目标是否处于低生命、护盾、防化服或最终阶段。
- 当前接敌槽位和路径拥挤度。

目标评分只影响选谁，攻击 Ability 仍在命中帧复核目标有效性。

### 11.3 接敌和动画

Unity 近战代码通过攻击点位置做 SphereCastNonAlloc 扫掠，同一次攻击命中后结束当前攻击。Unreal 当前正式方案通过 Montage Notify 驱动可见命中窗口，两者共同说明：

- 攻击开始、有效命中窗口和攻击结束必须分开。
- 每个目标在一次攻击内只结算一次，除非技能明确允许多段。
- 站位、碰撞半径、攻击距离和动画手臂伸展一起调节。
- 接敌槽位满时保留目标记忆，避免全部 Zombie 挤到目标中心。

## 12. UI 与表现

### 12.1 现有 UI 生命周期

Experience Manager 为每个 HUD 找到 OwningPlayer 和 LocalPlayer，然后：

- 把根布局推入 CommonUI 层。
- 把稳定 HUD 片段注册到 UIExtension 插槽。
- Experience 卸载时 DeactivateWidget 并注销 ExtensionHandle。

生化 HUD 沿用这一模式。每个分屏玩家只读取自己的 PlayerState、技能槽、角色状态和本地输入图标。

### 12.2 生化 HUD 数据

建议增加：

- Round 阶段、当前回合、剩余时间和阶段倒计时。
- AliveHumanCount、ActiveZombieCount、PermanentDeadCount。
- 当前 Team、Role、感染状态、免疫和待感染剩余时间。
- LastHuman、FinalPhase、逃亡阶段和目标进度。
- 当前角色生命、护盾、护甲、恢复和控制状态。
- 四槽技能、等级、模式、可用性、冷却和角色限制。
- 重生倒计时、观战状态和永久淘汰状态。
- 击杀、感染、抵抗、解毒、终结和奖励提示。

计数、阶段和角色状态来自 GameState 或 PlayerState。Widget 不读取 GameMode，不扫描全局 Actor 列表来判断胜负。

### 12.3 消息和 ViewModel

- GameState OnRep 触发 Round、Count、Objective、FinalPhase 和 Victory 消息。
- PlayerState OnRep 触发 Team、Role、Infection、Death、Respawn 和 Progress 消息。
- SkillLoadoutComponent 继续广播 Msg_Skill_LoadoutChanged。
- AttributeViewModel 处理 Health、Shield、MoveSpeed 和其他标量属性。
- 复杂数组使用整体快照刷新，避免为每个容器元素建立隐含状态。
- GameplayCue 负责感染、变身、抵抗、重生、终结和阶段变化的世界表现。

### 12.4 Unity UI 参考细节

可转译的表现包括：

- EnemyCounter 的敌方人口显示。
- Objective HUD 的主目标、次目标、可选目标、阻塞目标和延迟显示。
- PlayerHealthBar、Armor、WorldspaceHealthBar。
- KillMark 的爆头、近战、手雷和特殊伤害图标。
- Killfeed 的伤害来源和武器信息。
- MinimapMarker 的队伍变化和死亡图标。
- Compass 的目标方向和敌人提示。
- Crosshair 的敌方指示、后坐力和瞄准状态。
- NotificationHUD 的感染、目标和奖励提示。

这些内容进入本地 HUD 表现层，不能复制 Unity 的全局单例和 FindObjectOfType 访问方式。

## 13. 网络、Listen Server 与分屏

### 13.1 权威边界

服务器权威写入：

- Match 和 Round 阶段。
- 初始感染选择。
- Team、Role、感染、抵抗、待感染和解毒。
- 伤害、死亡、永久淘汰和重生。
- 人口、LastHuman、FinalPhase、地图目标和胜负。
- 技能获得、升级、冷却和角色适用状态。
- 奖励、金币、经验和商店事务。

客户端负责：

- 输入请求。
- 本地预测允许的移动和技能表现。
- 读取复制状态并展示 UI、动画和 Cue。

Listen Server Host 同时运行服务器和本地玩家视图，不能用 IsLocallyControlled、LocalPlayer 或 PlayerController 本地身份替代 HasAuthority。

### 13.2 复制粒度

- GameState 复制公共 Round 快照和人口。
- PlayerState 复制自己的 Team、Role、感染、死亡、重生和 Match Skill OwnerOnly 数据。
- Pawn 复制当前形态、死亡状态、移动和表现状态。
- ASC 复制 AbilitySpec、GameplayEffect、GameplayTag 和 Cue 所需的状态。
- UI 通过 OnRep、GameplayMessage 和 ViewModel 形成单一显示链。

玩家感染后如果替换 Pawn，PlayerState 仍是玩家身份的稳定引用。UI 重新绑定 Avatar 时不能创建第二个技能或属性来源。

### 13.3 分屏隔离

- 所有玩家私有 UI 通过对应 LocalPlayer 的 PrimaryGameLayout 和 UIExtension。
- 技能栏按 Owning PlayerState 过滤消息。
- 交互、重生、技能获取和目标提示使用目标 PlayerController。
- 不使用 GetFirstPlayerController、GetPlayerController(0) 或没有 OwningPlayer 的 CreateWidget。
- AI 目标和服务器人口不按本地屏幕索引判断。

## 14. 存档、物品和生命周期

### 14.1 生命周期分层

| 代码事实 | 对生化模式的影响 | Unreal 处理 |

| Actor.isPlayer 和多处 EGameMode 分支决定敌我 | 玩家身份和阵营被绑定，无法支持感染后角色变化 | 全部使用 ILyraTeamAgentInterface、TeamId、RoleTag 和 Role AbilitySet |

## 19. C++ 与 GAS 实现草稿

### 19.1 设计结论

生化模式的公共基础只保留四个稳定职责：

1. UShootAttributeSet 负责 Shield 到 Health 的 GAS 伤害结算。
2. Health 归零时发送 Event.Health.Depleted。
3. 当前 Experience 通过 AbilitySet 授予一个健康归零响应 Ability。
4. 响应 Ability 调用死亡链或角色转换服务。

模式差异由 Experience 选择的 AbilitySet、GameplayAbility、GameplayEffect、GameplayTag、Role Definition 和 PawnData 组合表达。草稿不定义通用感染枚举、规则表或过程式感染求值器。

基础感染不需要感染计数器。普通 Zombie 攻击使用带有感染语义标签的普通伤害 GE，Human Health 归零后由 InfectionOnHealthDepleted Ability 变成 Zombie。直接感染只把 Zombie 的攻击 Ability 或 Impact GE 换成直接作用于 Health 的版本，穿透 Shield 并让 Health 归零。防化服是 Human Skill 或 Role Ability 的一次性应用免疫行为，免疫在伤害效果执行前生效，完全抵消该次感染攻击，不扣 Health，也不恢复 Health。两次攻击通过普通伤害数值让 Health 经过两次命中归零。

### 19.2 当前代码事实和必须拆开的边界

当前 UShootAttributeSet::HandleIncomingDamage 已经完成：

- 读取 IncomingDamage。
- 按 Shield 优先、Health 次之的顺序扣除伤害。
- 通过 Status.ImmuneDeath 将最低 Health 保持为 1。
- 发送实际伤害表现。
- Health 从正数跨到 0 时调用 ICombatInterface::Die。
- 通知 AShootGameModeBase::NotifyCharacterKilled。

当前 AShootCharacterBase::Die 会进入 StartDeath，停止移动、关闭碰撞、广播死亡、取消全部 Ability 和移除 GameplayCue。这条链适合 PVE 人类死亡和 Zombie 死亡，不适合先死亡再变成 Zombie。

必须把最后一步拆成通用事件入口：

~~~cpp
if (FinalHealth <= 0.0f && Context.TargetASC)
{
    FGameplayEventData EventData;
    EventData.Instigator = Context.SourceActor.Get();
    EventData.Target = Context.TargetActor.Get();

    Context.TargetASC->HandleGameplayEvent(
        FShootGameplayTags::Get().Event_Health_Depleted,
        &EventData);
}
~~~

健康归零事件还必须覆盖直接感染的 GAS 路径。直接感染的 Impact GameplayEffect 使用专用 Execution 直接对 Health 产生足以归零的负向 Modifier，不写入 IncomingDamage，所以不经过 Shield 吸收。普通伤害和直接感染在效果完成后都调用同一个健康归零事件出口，响应 Ability 不需要知道伤害来自哪一种攻击。

直接感染的 Execution 不调用 AttributeSet 的 `SetHealth`，不写死伤害数值，默认不清理 Shield。它只通过 GAS 修改 Health，并让公共健康归零事件出口通知当前 Experience 选择的响应 Ability。

UShootAttributeSet 不认识 PVE、感染、直接感染或防化服。死亡统计由 DeathOnHealthDepleted Ability 或对应死亡对象执行，感染转换由 InfectionOnHealthDepleted Ability 执行。移除当前直接调用 Die 前，必须先为现有 PVE Experience 配好死亡响应能力，确保大灾变模式仍然是人类扣血归零死亡。

### 19.3 健康归零响应的面向对象结构

健康归零响应使用一个抽象 Ability 基类和多个具体实现。Experience 为同一个 Role 选择其中一个响应能力，不在 AttributeSet 里写模式分支。

~~~cpp
UCLASS(Abstract)
class UShootGA_HealthDepletedResponse : public UShootGameplayAbility
{
    GENERATED_BODY()

protected:
    virtual void RespondToHealthDepleted(
        const FGameplayEventData& EventData) PURE_VIRTUAL(
            UShootGA_HealthDepletedResponse::RespondToHealthDepleted, );
};

UCLASS()
class UShootGA_DeathOnHealthDepleted
    : public UShootGA_HealthDepletedResponse
{
    GENERATED_BODY()

protected:
    virtual void RespondToHealthDepleted(
        const FGameplayEventData& EventData) override;
};

UCLASS()
class UShootGA_InfectionOnHealthDepleted
    : public UShootGA_HealthDepletedResponse
{
    GENERATED_BODY()

protected:
    virtual void RespondToHealthDepleted(
        const FGameplayEventData& EventData) override;
};

UCLASS()
class UShootGA_HazmatInfectionResistance
    : public UShootGameplayAbility
{
    GENERATED_BODY()

protected:
    virtual void ConsumeBlockedInfection(
        const FGameplayEventData& EventData);
};
~~~

DeathOnHealthDepleted 调用现有 Die 和死亡统计。InfectionOnHealthDepleted 调用 Role Transition Service，不调用 Die、StartDeath 或通用 PlayerDied。HazmatInfectionResistance 不继承健康归零响应，它通过自己的免疫 GameplayEffect 在感染 Impact GameplayEffect 执行前拦截伤害，并在有效命中后的感染尝试事件中消耗一次防护资格。

防化服的次数、持续时间和被什么攻击消耗由该 Ability 与 GameplayEffect 自己拥有。防化服免疫只匹配带有 `Damage.Infection` 的感染 Impact GameplayEffect，不拦截普通 PVE 伤害。抵消成功时没有 IncomingDamage，没有 Health 归零事件，也没有 Health 恢复。现有 UShootEffect_ImmuneDeath 只表示持续时间型的免死标签，不能直接当成一次性防化服。

### 19.4 PVE Zombie 与生化 Zombie 的 AbilitySet 隔离

当前 AEnemyBotController、AEnemyBotCharacter 和 UShootGA_ZombieMelee 是 PVE 打僵尸链的局部实现，整体仍是半成品。该链的语义是：

- Zombie 由 AI 控制。
- BehaviorTree 请求 Zombie 近战 GAS Ability。
- 命中 Notify 打出普通伤害 GE 和攻击状态 GE。
- Human Health 归零后进入死亡。
- Zombie 被击杀后由当前 PVE 规则决定重生或死亡。

这套代码不包含生化感染。生化模式只复用已经成熟的目标验证、攻击动画和命中窗口，能力资产保持隔离：

| Experience | Human 归零响应 | Zombie 攻击 Ability | 归零结果 |
| --- | --- | --- | --- |
| CF 或 CSOL 大灾变 PVE | DeathOnHealthDepleted | ZombieMeleeDamage | 人类死亡，不改变 Team 和 Role |
| 基础生化感染 | InfectionOnHealthDepleted | ZombieMeleeDamage | 人类转换为 Zombie，继续参与 Round |
| 直接感染 | InfectionOnHealthDepleted | ZombieMeleeInfection | 直接 Impact GE 或 Execution 穿透 Shield 将 Health 清空，随后转换 |
| 防化服变体 | 独立的 HazmatInfectionResistance | 当前 Experience 选择的 Zombie Ability | 感染 Impact GE 执行前被拦截，防护消耗一次，Health 不变 |

AI 只请求语义明确的 Zombie 近战 Ability Tag。到底授予普通伤害 Ability 还是感染 Ability，由 Experience 和 Role AbilitySet 决定，AI 不读取 Experience 名称。

### 19.5 Zombie 近战 Ability 的面向对象结构

当前 UShootGA_ZombieMelee 的公共流程是攻击激活、目标保存、Montage、命中 Notify、服务器目标复核、攻击 GE 和冷却。若 PVE 与生化只差 Impact GE，继续使用同一个 GA CDO，通过不同 AbilitySet 配置不同 GE。若攻击语义确实不同，再提取公共基类：

~~~cpp
UCLASS(Abstract)
class UShootGA_ZombieMeleeBase : public UShootGameplayAbility
{
    GENERATED_BODY()

protected:
    virtual void ExecuteMeleeImpact(AActor* TargetActor) PURE_VIRTUAL(
        UShootGA_ZombieMeleeBase::ExecuteMeleeImpact, );

    void ValidateTargetAtImpact(AActor* TargetActor) const;
    void PlayAttackMontage();
};

UCLASS()
class UShootGA_ZombieMeleeDamage : public UShootGA_ZombieMeleeBase
{
    GENERATED_BODY()

protected:
    virtual void ExecuteMeleeImpact(AActor* TargetActor) override;
};

UCLASS()
class UShootGA_ZombieMeleeInfection : public UShootGA_ZombieMeleeBase
{
    GENERATED_BODY()

protected:
    virtual void ExecuteMeleeImpact(AActor* TargetActor) override;
};
~~~

UShootGA_ZombieMeleeDamage 使用当前 AttackEffectClass 和 AttackStatusEffectClass。UShootGA_ZombieMeleeInfection 使用感染 Experience 选择的普通伤害 GE 或直接作用于 Health 的 GE/Execution。生化攻击效果统一带有 `Damage.Infection` 标签，供防化服的应用免疫拦截；普通 PVE 攻击不带该标签。能力本身不调用 ChangeTeam，也不直接修改 Target AttributeSet。

当前近战 GA 可能分别应用伤害 GE 和攻击状态 GE。防化服要求整次感染攻击完全免疫，因此感染 Ability 优先使用一个同时承载伤害和感染状态的 Infection Impact GE；如果继续拆成多个 GE，所有相关 GE 都必须带有 `Damage.Infection` 并受同一个应用免疫效果拦截，不能只拦截其中一个。

当前 UShootGA_ZombieMelee 的命中时序必须保持：

- HandleMeleeNotify 是 bHitApplied 的唯一写入点。
- ExecuteMeleeHit 不能重复使用已经置 true 的 bHitApplied 作为入口拦截。
- AnimNotify 只产生命中窗口信号。
- 服务器命中帧重新验证距离、视线、Team Attitude、死亡状态和目标。
- 一次攻击只应用一次直接伤害，状态 GE 是否附带由当前 Ability 或 CDO 配置决定。
- AI Zombie 使用 Enemy Character ASC，玩家 Zombie 使用 PlayerState ASC，两者分别保存和回收 Role AbilitySet 句柄。

### 19.6 四种玩法的 GAS 表达

基础感染：

- Human Role AbilitySet 授予 InfectionOnHealthDepleted。
- Zombie Role AbilitySet 授予普通伤害攻击。
- 普通攻击通过 IncomingDamage 将 Health 扣到 0。
- Event.Health.Depleted 激活感染响应，Role Transition Service 将玩家转入 Zombie Team 和 Zombie Role。

直接感染：

- Zombie Role AbilitySet 授予 ZombieMeleeInfection，或者给同一近战 Ability 的 CDO 配置清空 Health 的 Impact GE。
- 直接 Impact GE 或 Execution 直接对 Health 产生足以归零的负向 Modifier，穿透 Shield，默认不修改 Shield。
- 该效果不写入 IncomingDamage，不走普通 Shield 吸收逻辑，但在效果完成后仍发送统一的 Event.Health.Depleted。
- InfectionOnHealthDepleted 不需要知道这次伤害来自普通攻击还是清空攻击。

防化服抵消一次：

- Human 的 Skill 或 Role AbilitySet 授予 HazmatInfectionResistance。
- 该 Ability 激活一次性免疫 GameplayEffect。该效果以 `Damage.Infection` 作为应用免疫标签，因此普通感染 Impact GE 和直接感染 Impact GE 都在执行前被拦截。
- 有效攻击命中后，Zombie Attack Ability 发送感染尝试事件，防化服 Ability 消耗一次资格。
- 被拦截的攻击不产生 IncomingDamage、Health 归零事件或 Health 恢复。防护消耗后，下一次攻击按当前 Experience 授予的感染 Ability 处理。
- 防化服不是 AttributeSet 的永久字段，也不是全局感染枚举。

两次攻击感染：

- Zombie 仍使用普通伤害 Ability。
- Experience 配置 Human 属性、Shield 和 Zombie 普通攻击 GE 的数值，让两次有效命中后 Health 归零。
- 基础感染链不记录通用感染命中次数。
- 如果未来需要与 Health 数值无关的严格两次命中，再单独实现一个有明确玩法语义的 Ability 或 GameplayEffect，不修改基础感染响应。

### 19.7 Role Transition Service

健康归零感染 Ability 已经决定转换后，只把执行事务交给 Role Transition Service：

~~~cpp
UCLASS()
class UShootRoleTransitionService : public UObject
{
    GENERATED_BODY()

public:
    bool ConvertHumanToZombie(
        AShootPlayerState& PlayerState,
        const UShootRoleDefinition& ZombieRole,
        const FGameplayEventData& SourceEvent);
};
~~~

事务顺序：

1. 锁定 PlayerState，确认服务器、当前 Round、当前 Role 和 DeathState。
2. 保存旧 Role AbilitySet 句柄、当前 Pawn、PawnData、四槽 Match Skill 记录、GrantedHandles 和逻辑冷却状态。
3. 回收 Human Role AbilitySet，保留 Common AbilitySet。
4. 更新 PlayerState 的 TeamId、RoleTag 和感染来源。
5. 按 Zombie Role Definition 选择替换 Pawn、PawnData 或同 Pawn 的形态转换。
6. 同 Pawn 时切换 CO 网格和动画实例，替换 Pawn 时重新绑定 PlayerState ASC 的 Owner 和新 Pawn Avatar。
7. 授予 Zombie Role AbilitySet，并保存独立句柄。
8. 让 SkillLoadoutComponent 按每个 SkillDefinition 的 Role Binding 处理四槽能力，槽位数据、等级、获得记录和逻辑冷却仍归 PlayerState。
9. 刷新 Controller、AI Perception、GameplayCue、UI 消息和 GameState 人口。
10. 最后检查 LastHuman、FinalPhase 和胜负。

Match Skill 的角色转换规则：

- 槽位记录不随 Pawn 销毁，不因感染清空，也不重新创建另一套四槽数据。
- 同一逻辑技能在新 RoleTag 下有绑定时，回收旧角色授予的 AbilitySpec 和 GrantedHandles，使用相同槽位、等级和输入标签授予新绑定。
- 新绑定使用同一个逻辑 CooldownTag 时，保留当前冷却剩余时间，感染不会通过换能力免费刷新技能。
- 新 RoleTag 没有绑定时，只回收该槽位当前 Role 的 AbilitySpec，槽位记录、等级和获得记录保留，运行时状态标记为暂停并广播给 UI。
- 人类专属的持续 GameplayEffect、动作锁、武器依赖和外观依赖随旧角色能力清理。角色通用效果只有在对应 SkillDefinition 明确绑定到新 Role 时才保留。
- 角色固有技能与 Match Skill 使用不同 AbilitySet 句柄。感染只重建 Role AbilitySet 和各槽位的角色绑定，不把所有能力合并后再用运行时条件过滤。

Role Transition Service 只执行转换，不解释攻击类型，不读取 Experience 名称，不拥有 Zombie 具体技能。Pawn、CO、AbilitySet 和技能替换都从 Role Definition、PawnData 和 AbilitySet 读取。

### 19.8 Pawn、CO 与外观

生化模式不使用 Unity 式隐藏人类网格伪造 Zombie，也不把网格显隐作为角色状态。

- Gameplay Role、Team 和能力状态归 PlayerState、ASC 和 Role Definition。
- 当前人类角色继续使用项目已有 CO 外观链。
- Zombie Pawn 和 Zombie CO 尚未确定，留给 Zombie PawnData 或 Zombie Role Definition 的资产决策。该资产选择不会改变 Team、Role、ASC 和 Match Skill 的转换协议。
- 如果 Zombie 使用独立 Pawn 或独立 CO，感染时替换 Pawn，并重新绑定 PlayerState ASC。
- 如果将来确认人类和 Zombie 能共用 Pawn、骨骼和碰撞，感染时可以在同一个 Pawn 内切换 CO 使用的网格和动画实例，再刷新角色碰撞、移动和表现参数。
- 感染逻辑不调用 SetVisibility，不隐藏人类部件，不强行修改 Mutable CO。

CO 是表现装配，Team、Role、AbilitySet 和 Health 归零响应不依赖 CO 的具体实现。

### 19.9 开工条件和实现顺序

当前具备开始 P0 的条件，但第一步必须先处理公共伤害链的死亡耦合：

1. 新增 Event.Health.Depleted，并让 UShootAttributeSet 发送事件。
2. 为现有 PVE Experience 配置 DeathOnHealthDepleted，验证人类和 Zombie 仍然只死亡。
3. 新增 InfectionOnHealthDepleted 和 Role Transition Service，验证基础健康归零感染。
4. 将 PVE Zombie AbilitySet 与感染 Zombie AbilitySet 分开。
5. 新增清空 Health 的 Infection Impact GE，验证直接感染。
6. 以独立 Hazmat Ability 实现一次性抵消。
7. 用普通伤害 GE 和属性配置验证两次命中归零。
8. 为各 Experience 选择既有 Zombie Death Policy，并验证普通死亡、特殊终结和无限重生。
9. 决定 Zombie PawnData、独立 Pawn 和 CO 方案后，接入角色表现适配器并验证同 Pawn 与换 Pawn 的路径。

以下玩法语义已经固定，代码和资产必须按此实现：

- 直接感染穿透 Shield，直接让 Health 归零，默认不修改 Shield。
- 防化服在感染 Impact GameplayEffect 执行前完整拦截该次攻击，Health 不变，不做 Health 恢复，防护资格消耗一次。
- 两次攻击使用普通伤害、Shield 和 Health 数值形成，不增加通用感染命中计数器。
- 感染转换必须同步 TeamId、RoleTag、角色能力、PlayerState ASC Avatar、角色表现和 Match Skill 角色绑定。
- Match Skill 保留槽位、SkillId、等级、获得记录和逻辑冷却；有 Zombie 绑定则切换，没有绑定则暂停但不删除。
- 普通 Zombie 死亡和重生由 Experience 选择 `PermanentDeath`、`RespawnUnlessSpecialKilled` 或 `InfiniteRespawn` 策略对象。

以下仍需资产或具体规则配置：

- Zombie 使用独立 Pawn、同 Pawn 角色切换还是其他形态承载方式。
- Zombie 是否拥有独立 CO，以及 Zombie 网格、AnimBP 和动画实例。
- 每个 Experience 具体选择的死亡策略、重生延迟、出生点、出生保护和特殊终结标签。
- 每个 Match Skill 的 Zombie 绑定、无绑定时的 UI 文案、角色固有技能优先级和武器转换表。

### 19.10 验收

- 大灾变 PVE 中，Human Health 归零激活 DeathOnHealthDepleted，Team 和 Role 不改变。
- 基础生化中，普通 Zombie 伤害把 Human Health 扣到 0 后激活 InfectionOnHealthDepleted。
- 直接感染使用清空 Health 的 Ability 或 GE，直接作用于 Health 并穿透 Shield，对不同 MaxHealth 的 Human 都不依赖硬编码血量。
- 防化服在感染 Impact GameplayEffect 执行前完整拦截第一次感染攻击，消耗一次资格，Health 不变且没有 Health 恢复，下一次有效攻击按当前感染规则处理。
- 两次攻击通过普通伤害结算归零，不存在基础感染命中计数器。
- PVE Zombie 与感染 Zombie 的 AbilitySet 不互相污染。
- 玩家 Zombie 的 PlayerState ASC、AI Zombie 的 Enemy Character ASC 都能独立授予和回收 Role AbilitySet。
- 人类感染后 TeamId、RoleTag、CO 网格、动画实例、Role AbilitySet 和 Match Skill 角色绑定同步完成；四槽记录、等级和逻辑冷却保留，无 Zombie 绑定的技能只暂停。
- 三种 Zombie Death Policy 均能按 Experience 选择，普通击杀、特殊终结、永久淘汰和无限重生进入各自策略。
- 角色外观转换不依赖隐藏网格和运行时修改 Mutable CO。
- 新增感染变体只新增或替换 Experience、AbilitySet、Ability、GameplayEffect、GameplayTag、PawnData 或 CO 配置，不在公共伤害链增加 Experience 分支。
