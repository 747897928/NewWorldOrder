# 生化模式规则与地图研究

# 外部规则基准

- CSOL 官方模式说明把基础生化模式定义为少量僵尸对多数人类：僵尸在限定时间内感染所有人类；人类坚持到时间结束或消灭所有僵尸。
- CSOL 生化模式 II 在基础追逃上加入人类补给与僵尸特殊技能；生化模式 III 加入英雄、士气、僵尸复活与进化。
- 首个版本采用基础规则，不立即加入 II/III 的全部成长系统，但预留补给点、感染者复活点和角色 AbilitySet。
- 官方资料：
  - https://csol.tiancity.com/homepage/v4/course/game_model.html
  - https://csol.tiancity.com/homepage/v4/course/course.html
  - https://csol.tiancity.com/homepage/event/battleroyale/main1.html
- CrossFire 官方补丁长期把 Mutation Mode 作为独立玩法，并包含感染者回复、跳跃强化等差异化能力。首个版本把这些作为可配置 AbilitySet，不写进角色基类。
- CrossFire 官方资料：
  - https://crossfire.z8games.com/article.html?id=3118541
  - https://crossfire.z8games.com/patches/october2016

# Nano.cs 现有规则复述

## 开局

- 场景启动后延迟 1 秒开始游戏。
- 所有 Actor 先切换为 Human 阵营。
- 进行默认 10 秒倒计时，倒计时为 0 时随机选择一个 Actor 变为 Nano。
- `canPlayerTurnNano=false` 时先从候选列表移除本地玩家，因此默认更倾向让 Bot 成为初始母体。

## 感染转换

- `PawnController.TurnNano` 先卸下并删除人类武器。
- 隐藏 Human 模型，显示 Nano 模型并重新初始化角色表现。
- 授予 Nano 起始武器。
- 把最大生命设为 500 并回满。
- 把阵营改为 Nano，广播 `TurnNanoEvent`。

## 胜负与重开

- 每次 `TurnNanoEvent` 后检查是否仍有 Human。
- 没有人类时播放 GhostWin，3 秒后重新加载当前场景。
- 新增 Bot 若阵营已是 Nano，会再次调用 `TurnNano` 恢复感染者配置。

# Nano.cs 不能直接照搬的缺口

- 只有“人类全部感染”一种胜负检查，没有回合时间结束的人类胜利。
- 没有完整回合数、比分、结算、下一回合和比赛结束状态机。
- 没有 Listen Server 权威、复制、晚加入或断线重连处理。
- 玩家死亡、感染者死亡和重生边界不完整；Bot 特殊处理不能成为正式规则。
- 事件监听没有看到对应解除，重复装载可能残留静态订阅。
- 没有防止重复结算的 RoundEnded 守卫。
- 生命值、武器和模型直接写在 Pawn 方法中，无法随 Experience 或角色类型数据驱动卸载。
- 没有地图守点、补给点、路线和感染者突破能力的配置层。

# 项目版基础规则

## 回合状态

- Waiting：等待最低玩家数或测试命令。
- Preparing：所有玩家重置为 Human，初始化副本属性与 RuntimeOnly 装备。
- Reveal：倒计时结束，服务器选择一个或按人数比例选择初始感染者。
- Active：允许攻击、感染、死亡和模式定义的重生。
- Ending：冻结胜负，广播结果，停止新的感染事务。
- Intermission：短暂结算后准备下一回合。
- MatchEnding：达到总回合数或获胜回合数，返回 Lobby 或 HomeMap。

## 基础胜负

- 感染者胜利：Active 阶段人类数量变为 0。
- 人类胜利：回合时间结束仍至少有一名人类。
- 是否允许“消灭所有感染者直接获胜”由模式配置决定；若感染者可无限复活则关闭该条件。

## 数据边界

- 回合属性、等级、技能和购买装备全部 RuntimeOnly。
- Experience 选择规则、PawnData、AbilitySet、HUD 与输入；GameMode 不从 SaveGame 创建战斗装备。
- 感染时服务器撤销 Human 句柄，再授予 Infected 句柄；角色基类不写阵营硬分支。
- 阵营识别统一使用 `ILyraTeamAgentInterface`。

# 白盒地图原则

## 尺度与层级

- 首版约 15000 × 12000 cm。
- 地面层 Z=0；中层守点约 Z=350 至 500；最高观察点约 Z=700 至 900。
- 外环完整跑通一圈的目标时间为 25 至 35 秒，并至少有三条横向连接，避免单一路线追逐。

## 三类守点

- A 仓库天桥：容量最大，正面坡道暴露且易被火力压制，同时保留较慢后侧绕路和可跳下撤离口。
- B 通风设备区：中等容量，正面窄口之外增加维护通道或顶部突破口，避免永久单门安全屋。
- C 观察塔：只容纳 2 至 3 人，视野好但至少有两条进攻方向；感染者高跳或后续能力可形成克制。

## 路线公平性

- 不建立只有一个入口且能无限击退防守的绝对安全点。
- 每个强守点都必须具备主攻路线、慢速侧路和撤离选择三者中的至少两项。
- 高点必须能被观察、被包抄或被能力克制；高度本身不是无条件安全。
- 感染者出生或复活点不能处在人类直接火力线内，应分布在外环遮挡后的 4 至 6 个口袋区。
- 预留 6 至 8 个补给候选点，但首版不实现补给系统也不阻塞白盒验收。

# 白盒验收

- 玩家能从任一主区域经至少两条不同路线到达其他主区域。
- 三个守点具有明显不同的容量、射界和退路，不是同一种平台的复制。
- 不使用跳跃漏洞、不可见碰撞或单像素边缘作为必要路线。
- Listen Server 下服务器与客户端位置、碰撞和出生点一致。
- 经过一轮无技能追逃测试后，任何守点都不能出现感染者永久无法触达的情况。
- 后续加入感染者高跳或冲刺时，只通过 AbilitySet 与地图标注调优，不重写基础角色移动分支。
